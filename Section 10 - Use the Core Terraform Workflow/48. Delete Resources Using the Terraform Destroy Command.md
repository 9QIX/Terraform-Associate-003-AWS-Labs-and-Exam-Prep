# Terraform Destroy Command

## Overview

The `terraform destroy` command removes all remote infrastructure resources managed by a Terraform configuration. It does **not** delete your Terraform code files (e.g., `main.tf`) or affect resources not managed by Terraform. This command is essential for cleaning up infrastructure without leaving technical debt—orphaned or unused resources that accumulate costs and clutter.

---

## Concepts

### What Terraform Destroy Does

- Destroys all resources tracked in the Terraform state file
- Requires explicit confirmation (`yes`) before execution
- Preserves all `.tf` configuration files
- Only affects resources managed by the current Terraform configuration

### What It Does NOT Do

- Delete Terraform configuration files
- Remove resources not imported into Terraform state
- Affect manually created infrastructure outside Terraform management

### Use Cases

- Cleaning up development or ephemeral environments
- Decommissioning temporary test infrastructure
- Removing all resources before reconfiguring from scratch

## Terraform Workflow

### Basic Destroy Command

```bash
terraform destroy
```

**Line-by-line Comments:**

```bash
# Initiates destruction of all managed resources
# Prompts for confirmation before proceeding
```

**Code Walkthrough:**

1. Terraform refreshes the state to identify all managed resources
2. Displays a destruction plan showing resources to be removed
3. Prompts: `Do you really want to destroy all resources?`
4. User must type `yes` to confirm (no abbreviations accepted)
5. Executes deletion in reverse dependency order

**Example Output:**

```shell
Plan: 0 to add, 0 to change, 39 to destroy.

Do you really want to destroy all resources?
  Terraform will destroy all your managed infrastructure, as shown above.
  There is no undo. Only 'yes' will be accepted to confirm.

  Enter a value: yes

...
Destroy complete! Resources: 39 destroyed.
```

---

### Auto-Approve Flag

```bash
terraform destroy -auto-approve
```

**Line-by-line Comments:**

```bash
# Destroys all resources without interactive confirmation
# Use with caution—no undo available
```

**Code Walkthrough:**

- Skips the confirmation prompt
- Immediately proceeds with resource destruction
- Useful for CI/CD pipelines or scripted teardowns
- **Warning:** No safety net—ensure you're targeting the correct environment

---

### Alternative: Apply with Destroy Flag

```bash
terraform apply -destroy
```

**Line-by-line Comments:**

```bash
# Equivalent to terraform destroy
# Uses apply workflow with destruction mode
```

**Code Walkthrough:**

- Functionally identical to `terraform destroy`
- Follows the `apply` command pattern
- Still requires confirmation unless combined with `-auto-approve`
- Useful for maintaining consistent command patterns in automation

## State Management

### Destruction Order

Terraform destroys resources in **reverse dependency order**:

1. Child resources (e.g., EC2 instances)
2. Intermediate resources (e.g., subnets, security groups)
3. Parent resources (e.g., VPCs, internet gateways)

### State File Behavior

- State file remains intact after destruction
- Contains historical metadata about destroyed resources
- Can be deleted manually if no longer needed

## Pitfalls & Best Practices

### Common Mistakes

| Mistake                               | Consequence                     | Solution                                               |
| ------------------------------------- | ------------------------------- | ------------------------------------------------------ |
| Running destroy in production         | Irreversible data loss          | Use workspaces or separate state files per environment |
| Forgetting `-auto-approve` in scripts | Manual intervention required    | Add flag for non-interactive environments              |
| Assuming destroy removes code         | Configuration files remain      | Manually delete `.tf` files if needed                  |
| Destroying shared resources           | Breaks dependent infrastructure | Use targeted destroy or modules                        |

### Best Practices

- **Always verify the environment** before running destroy
- **Review the destruction plan** carefully—there is no undo
- **Use workspaces** to isolate dev/staging/prod environments
- **Backup state files** before large-scale destruction
- **Avoid destroying long-lived production resources** unless decommissioning
- **Re-run `terraform apply`** after lab exercises to restore infrastructure for subsequent lessons

### Technical Debt Prevention

Terraform destroy eliminates orphaned resources that accumulate when manually deleting infrastructure:

- No forgotten subnets, security groups, or endpoints
- Complete cleanup of all dependencies
- Prevents cost overruns from unused resources

## Common Exam Traps

- **Trap:** Believing `terraform destroy` deletes configuration files  
  **Reality:** Only infrastructure is destroyed; `.tf` files remain intact

- **Trap:** Assuming destroy affects all AWS resources  
  **Reality:** Only resources in the Terraform state are destroyed

- **Trap:** Thinking destroy can be undone  
  **Reality:** Destruction is permanent; must re-run `terraform apply` to recreate

- **Trap:** Confusing `terraform destroy` with `terraform apply -destroy`  
  **Reality:** Both commands are functionally identical

- **Trap:** Forgetting confirmation is required  
  **Reality:** Must type `yes` explicitly (not `y` or `Y`)
