# Generate and Review an Execution Plan with `terraform plan`

## Overview

The `terraform plan` command performs a dry-run of Terraform configuration execution, showing proposed changes without making actual modifications to infrastructure. It compares current state with desired configuration, identifies differences, and creates an execution plan that can be reviewed before applying changes.

## Concepts

### Planning Fundamentals

- **Dry-Run Execution**: Preview changes without applying them
- **State Comparison**: Compare current state with desired configuration
- **Change Detection**: Identify additions, modifications, and deletions
- **Safe Operation**: No infrastructure changes during planning
- **Execution Preview**: Shows exactly what `terraform apply` would do

### Key Benefits

- Risk mitigation through change preview
- Team collaboration and review processes
- Change validation before execution
- Drift detection capabilities
- Plan persistence for later execution

## Terraform Workflow

### Basic Plan Generation

```bash
terraform plan
```

**Line-by-line Comments:**

```bash
# Generate execution plan showing proposed changes
```

**Code Walkthrough:**
The plan command performs three key steps: reads current state of existing remote objects, compares current configuration to prior state, and proposes change actions to make remote objects match configuration.

### Plan Process Steps

1. **State Reading**: Refresh current state of existing remote objects
2. **Configuration Comparison**: Compare current configuration to prior state
3. **Change Proposal**: Generate set of actions to achieve desired state

### Plan Output Symbols

| Symbol | Meaning | Action                                   |
| ------ | ------- | ---------------------------------------- |
| `+`    | Create  | Resource will be created                 |
| `-`    | Destroy | Resource will be destroyed               |
| `~`    | Update  | Resource will be updated in-place        |
| `-/+`  | Replace | Resource will be destroyed and recreated |

## State Management

### Plan File Persistence

```bash
terraform plan -out=myplan
```

**Line-by-line Comments:**

```bash
# Save execution plan to file for later use
```

**Code Walkthrough:**
Saving plans to files guarantees exact execution of reviewed changes. The plan file contains all proposed changes and can be applied later using `terraform apply myplan`.

### Plan File Inspection

```bash
terraform show myplan
```

**Line-by-line Comments:**

```bash
# Display contents of saved plan file
```

**Code Walkthrough:**
The show command reveals detailed information about saved plans, including all proposed changes, resource attributes, and execution order.

### No Change Plans

```text
No changes. Your infrastructure matches the configuration.

Terraform has compared your real infrastructure against your configuration and found no differences, so no changes are needed.
```

**Code Walkthrough:**
No Change Plans (also called Zero Change Plans) indicate perfect synchronization between configuration and deployed infrastructure. This validates that no drift has occurred and refactoring exercises were benign.

## Terraform Workflow

### Refresh-Only Plans

```bash
terraform plan -refresh-only
```

**Line-by-line Comments:**

```bash
# Update state file with current infrastructure state
```

**Code Walkthrough:**
Refresh-only plans update Terraform state to match current infrastructure without proposing configuration changes. Useful for detecting and reconciling manual changes made outside Terraform.

### Drift Detection Example

**Manual Change Detection:**

```text
Note: Objects have changed outside of Terraform

Terraform detected the following changes made outside of Terraform since the last "terraform apply":

  # aws_instance.web_server has been changed
  ~ resource "aws_instance" "web_server" {
        id                                   = "i-0da540d207d546644"
      ~ tags                                 = {
          + "Team" = "Engineering"
            # (1 unchanged element hidden)
        }
      ~ tags_all                             = {
          + "Team"        = "Engineering"
            # (4 unchanged elements hidden)
        }
        # (27 unchanged attributes hidden)
    }

This is a refresh-only plan, so Terraform will not take any actions to undo these. If you were expecting these changes then you can apply this plan to record the updated values in the Terraform state without changing any remote objects.
```

**Code Walkthrough:**
The refresh-only plan detected a manually added tag in the AWS console. It shows the difference between Terraform's recorded state and actual infrastructure state, enabling drift detection and state reconciliation.

### Plan Command Options

```bash
terraform plan -help
```

**Common Options:**

- `-out=FILE`: Save plan to file
- `-refresh-only`: Only refresh state, don't plan changes
- `-target=RESOURCE`: Focus on specific resource
- `-var="key=value"`: Set variable values
- `-var-file=FILE`: Load variables from file
- `-destroy`: Create destruction plan

## Pitfalls & Best Practices

### Critical Considerations

- **No Infrastructure Impact**: Plans never modify actual infrastructure
- **State Dependency**: Requires current state file for accurate planning
- **Change Validation**: Always review plans before applying
- **Team Collaboration**: Share plans for review before execution

### Common Mistakes

- Skipping plan review before applying changes
- Not saving plans for complex deployments
- Ignoring drift detection warnings
- Assuming plans guarantee successful applies
- Not using refresh-only for drift detection

### Best Practices

- Always run plan before apply in production
- Save plans for critical infrastructure changes
- Use refresh-only plans for drift detection
- Review plan output thoroughly before execution
- Include planning in CI/CD pipeline workflows
- Use targeted plans for focused changes
- Document and share plans for team review

## Key Terms & Definitions

- **Execution Plan**: Detailed description of changes Terraform will make
- **Dry Run**: Preview of operations without actual execution
- **Plan File**: Saved execution plan for later application
- **No Change Plan**: Plan showing no differences between state and configuration
- **Refresh-Only Plan**: Plan that only updates state without proposing changes
- **Drift Detection**: Identifying differences between managed and actual infrastructure

## Common Exam Traps

- **No Infrastructure Changes**: Plans never modify actual infrastructure
- **State Refresh**: Plans automatically refresh state before comparison
- **Plan Persistence**: Saved plans can be applied later by anyone
- **Refresh-Only Purpose**: Updates state to match current infrastructure
- **Safe Operation**: Can be run repeatedly without side effects
- **Change Symbols**: Different symbols indicate different types of changes
