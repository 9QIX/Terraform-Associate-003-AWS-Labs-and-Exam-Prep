# Execute Changes to Infrastructure with `terraform apply`

## Overview

The `terraform apply` command executes actions proposed in a Terraform plan, provisioning, modifying, or destroying infrastructure to match the desired state defined in configuration files. It updates the state file to reflect changes and operates only on resources managed by Terraform in the current working directory or workspace.

## Concepts

### Apply Fundamentals

- **Execution**: Implements changes proposed in execution plans
- **State Updates**: Modifies state file to reflect infrastructure changes
- **Resource Lifecycle**: Can create, update, or destroy resources
- **Workspace Scope**: Only affects resources in current workspace
- **Confirmation**: Requires approval unless auto-approved

### Key Benefits

- Automated infrastructure provisioning
- Consistent state management
- Safe execution with confirmation prompts
- Plan integration for predictable changes
- Selective resource targeting capabilities

## Terraform Workflow

### Basic Apply with Interactive Confirmation

**Configuration Change:**

```hcl
resource "aws_vpc" "vpc" {
  cidr_block = var.vpc_cidr

  tags = {
    Name        = var.vpc_name
    Environment = "stage"
    Terraform   = "true"
  }
}
```

**Line-by-line Comments:**

```hcl
# VPC resource definition
# CIDR block from variable
# Tags block with updated Environment value
# Changed from "demo_environment" to "stage"
```

**Code Walkthrough:**
Modifying the Environment tag triggers an in-place update. The apply command will detect this change, create an execution plan, and prompt for confirmation before applying.

```bash
terraform apply
```

## State Management

### Auto-Approve Apply

**Configuration Update:**

```hcl
resource "aws_vpc" "vpc" {
  cidr_block = var.vpc_cidr

  tags = {
    Name        = var.vpc_name
    Environment = "QA"
    Terraform   = "true"
  }
}
```

**Line-by-line Comments:**

```hcl
# VPC resource with updated tag
# Environment changed to "QA"
```

**Apply with Auto-Approve:**

```bash
terraform apply -auto-approve
```

**Output:**

```text
Terraform will perform the following actions:

  # aws_vpc.vpc will be updated in-place
  ~ resource "aws_vpc" "vpc" {
        id                               = "vpc-08b492b03641cb916"
      ~ tags                             = {
          ~ "Environment" = "stage" -> "QA"
            # (2 unchanged elements hidden)
        }
      ~ tags_all                         = {
          ~ "Environment" = "stage" -> "QA"
            # (4 unchanged elements hidden)
        }
        # (14 unchanged attributes hidden)
    }

Plan: 0 to add, 1 to change, 0 to destroy.
aws_vpc.vpc: Modifying... [id=vpc-08b492b03641cb916]
aws_vpc.vpc: Modifications complete after 1s [id=vpc-08b492b03641cb916]

Apply complete! Resources: 0 added, 1 changed, 0 destroyed.
```

**Code Walkthrough:**
The `-auto-approve` flag bypasses the confirmation prompt, immediately executing the plan. This is useful for automated pipelines but should be used cautiously as it eliminates the manual review step.

### Saved Plan Execution

**Configuration Update:**

```hcl
resource "aws_vpc" "vpc" {
  cidr_block = var.vpc_cidr

  tags = {
    Name        = var.vpc_name
    Environment = "test-dev"
    Terraform   = "true"
  }
}
```

**Line-by-line Comments:**

```hcl
# VPC resource with updated tag
# Environment changed to "test-dev"
```

**Create and Apply Saved Plan:**

```bash
terraform plan -out=myplan
terraform apply myplan
```

**Line-by-line Comments:**

```bash
# Save execution plan to file
# Apply saved plan without confirmation
```

**Output:**

```text
aws_vpc.vpc: Modifying... [id=vpc-08b492b03641cb916]
aws_vpc.vpc: Modifications complete after 2s [id=vpc-08b492b03641cb916]

Apply complete! Resources: 0 added, 1 changed, 0 destroyed.
```

**Code Walkthrough:**
Applying a saved plan file executes exactly what was reviewed and saved, without generating a new plan or requiring confirmation. This ensures reviewed changes are applied precisely as planned.

## Terraform Workflow

### Apply Behavior Comparison

| Method             | Confirmation | Use Case                                      |
| ------------------ | ------------ | --------------------------------------------- |
| **Standard Apply** | Required     | Manual operations, production changes         |
| **Auto-Approve**   | Skipped      | Automated pipelines, development environments |
| **Saved Plan**     | Not required | Reviewed changes, team approvals              |

### Resource Operation Types

| Operation   | Description                        | Example                        |
| ----------- | ---------------------------------- | ------------------------------ |
| **Create**  | Add new resources                  | New VPC, EC2 instance          |
| **Update**  | Modify existing resources in-place | Tag changes, attribute updates |
| **Replace** | Destroy and recreate resources     | Changes requiring replacement  |
| **Destroy** | Remove resources                   | Deleted from configuration     |

## Pitfalls & Best Practices

### Critical Considerations

- **Workspace Scope**: Only affects resources in current workspace
- **Unmanaged Resources**: Never touches resources not in state
- **Replacement Risk**: Some changes require resource recreation
- **State Updates**: Always updates state file after execution
- **Auto-Approve Caution**: Use carefully in production environments

### Common Mistakes

- Using auto-approve without reviewing changes
- Not understanding which changes cause replacements
- Applying without reviewing plan output
- Forgetting to save important plans for review
- Not coordinating applies in team environments

### Best Practices

- Review plan output before confirming apply
- Use saved plans for production deployments
- Reserve auto-approve for automated, tested workflows
- Coordinate applies with team members
- Monitor apply output for errors or warnings
- Backup state files before major changes
- Use version control for configuration changes

## Key Terms & Definitions

- **Apply**: Execute planned changes to infrastructure
- **Auto-Approve**: Skip confirmation prompt during apply
- **In-Place Update**: Modify resource without recreation
- **Replacement**: Destroy and recreate resource for certain changes
- **Saved Plan**: Pre-generated execution plan stored in file
- **Confirmation Prompt**: Interactive approval request before execution

## Common Exam Traps

- **Plan Not Required**: Can run apply without separate plan command
- **Auto-Approve Risk**: Bypasses safety confirmation prompt
- **Saved Plan Behavior**: No confirmation when applying saved plans
- **Workspace Isolation**: Only affects current workspace resources
- **State Updates**: Always updates state file after successful apply
- **Unmanaged Resources**: Never affects resources not in Terraform state
