# Variable Collection and Structure Types

## Overview

Terraform supports several value types beyond simple strings and booleans. This lab introduces **collection and structural types** — lists and maps — and demonstrates how to declare them as input variables, reference individual elements by index or key, and iterate over them with `for_each` to create multiple resources from a single resource block.

---

## Concepts

### Terraform Value Types

| Category   | Type         | Description                                                         | Example                        |
| ---------- | ------------ | ------------------------------------------------------------------- | ------------------------------ |
| Primitive  | `string`     | Unicode text                                                        | `"us-east-1a"`                 |
| Primitive  | `number`     | Integer or decimal                                                  | `15`, `6.2831`                 |
| Primitive  | `bool`       | Boolean                                                             | `true`, `false`                |
| Collection | `list(type)` | Ordered sequence of like-typed values; accessed by zero-based index | `["us-east-1a", "us-east-1b"]` |
| Collection | `map(type)`  | Key/value pairs; accessed by named key                              | `{ prod = "10.0.150.0/24" }`   |
| Structural | `tuple`      | Ordered sequence that allows mixed types                            | `["name", 52, true]`           |
| Structural | `object`     | Named attributes that may differ in type                            | `{ name = "Mabel", age = 52 }` |

- **Primitive types** (`string`, `number`, `bool`) hold single scalar values.
- **Collection / structural types** (`list`, `map`, `tuple`, `object`) hold multiple values and are the focus of this lab.
- Lists use a zero-based integer index; maps use named string keys.
- A **map of maps** (type `map(any)`) groups multiple attributes per key, enabling richer per-environment configuration in a single variable.

---

## Terraform Workflow

1. **Task 1** — Declare a `list(string)` variable; reference a specific element by index.
2. **Task 2** — Declare a `map(string)` variable; reference values by key and by another variable's value.
3. **Task 3** — Use `for_each` to iterate over a map and create one resource per key.
4. **Task 4** — Declare a `map(any)` (map of maps) to group multiple per-environment attributes; use `each.value.<attribute>` to access nested values.

## Task 1: List Variable and Index Access

### Variable Declaration

```hcl
variable "us-east-1-azs" {
  type = list(string)
  default = [
    "us-east-1a",
    "us-east-1b",
    "us-east-1c",
    "us-east-1d",
    "us-east-1e"
  ]
}
```

```hcl
# Line-by-line Comments
variable "us-east-1-azs" {          # variable name
  type = list(string)                # declares a list whose elements must all be strings
  default = [                        # default value — a list literal
    "us-east-1a",                    # index 0
    "us-east-1b",                    # index 1
    "us-east-1c",                    # index 2
    "us-east-1d",                    # index 3
    "us-east-1e"                     # index 4
  ]
}
```

### Incorrect Reference (causes plan error)

```hcl
resource "aws_subnet" "list_subnet" {
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = "10.0.200.0/24"
  availability_zone = var.us-east-1-azs   # ERROR: list passed where string is expected
}
```

**Why it fails:** `availability_zone` expects a single `string`. Passing the entire list produces a type mismatch error at plan time.

### Correct Reference (index access)

```hcl
resource "aws_subnet" "list_subnet" {
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = "10.0.200.0/24"
  availability_zone = var.us-east-1-azs[0]
}
```

```hcl
# Line-by-line Comments
resource "aws_subnet" "list_subnet" {
  vpc_id            = aws_vpc.vpc.id       # references another resource's id attribute
  cidr_block        = "10.0.200.0/24"      # static CIDR (will be replaced in Task 2)
  availability_zone = var.us-east-1-azs[0] # [0] selects the first element: "us-east-1a"
}
```

**Code Walkthrough:**

- List elements are accessed using `[index]` notation. Index `0` returns `"us-east-1a"`, index `1` returns `"us-east-1b"`, and so on.
- Passing a list variable without an index to an argument that expects a string causes a plan error — Terraform performs type-checking at plan time.

```bash
terraform plan    # verify us-east-1a is selected
terraform apply   # create the subnet
```

## Task 2: Map Variable and Key Access

### Variable Declaration

```hcl
variable "ip" {
  type = map(string)
  default = {
    prod = "10.0.150.0/24"
    dev  = "10.0.250.0/24"
  }
}
```

```hcl
# Line-by-line Comments
variable "ip" {
  type = map(string)       # a map whose values must all be strings
  default = {
    prod = "10.0.150.0/24" # key "prod", value "10.0.150.0/24"
    dev  = "10.0.250.0/24" # key "dev",  value "10.0.250.0/24"
  }
}
```

### Static Key Reference

```hcl
resource "aws_subnet" "list_subnet" {
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = var.ip["prod"]
  availability_zone = var.us-east-1-azs[0]
}
```

```hcl
# Line-by-line Comments
cidr_block = var.ip["prod"]   # selects the value associated with key "prod": "10.0.150.0/24"
```

### Dynamic Key Reference (using another variable)

```hcl
resource "aws_subnet" "list_subnet" {
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = var.ip[var.environment]
  availability_zone = var.us-east-1-azs[0]
}
```

```hcl
# Line-by-line Comments
cidr_block = var.ip[var.environment]
# var.environment — an existing string variable (e.g., default = "dev")
# var.ip["dev"]   — resolves to "10.0.250.0/24" when environment = "dev"
# var.ip["prod"]  — resolves to "10.0.150.0/24" when environment = "prod"
```

**Code Walkthrough:**

- Map values are accessed using `["key"]` notation.
- Using another variable as the key (`var.ip[var.environment]`) allows the same resource block to serve multiple environments without code duplication.
- When `var.environment` defaults to `"dev"`, `var.ip[var.environment]` resolves to `"10.0.250.0/24"`.

```bash
terraform plan              # verify CIDR reflects the current value of var.environment
terraform apply -auto-approve
```

## Task 3: `for_each` to Create Multiple Resources from a Map

### Configuration

```hcl
resource "aws_subnet" "list_subnet" {
  for_each          = var.ip
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = each.value
  availability_zone = var.us-east-1-azs[0]
}
```

```hcl
# Line-by-line Comments
resource "aws_subnet" "list_subnet" {
  for_each          = var.ip      # iterates over the map; creates one resource instance per key
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = each.value  # each.value = the map value for the current key (e.g., "10.0.150.0/24")
  availability_zone = var.us-east-1-azs[0]
  # each.key would give the current key string (e.g., "prod" or "dev")
}
```

**Code Walkthrough:**

- `for_each` accepts a map or a set of strings. When given a map, Terraform creates one resource instance per key.
- Inside the block, `each.key` holds the current iteration's key and `each.value` holds the current iteration's value.
- Resource addresses become `aws_subnet.list_subnet["dev"]` and `aws_subnet.list_subnet["prod"]` — the key is embedded in the address. This makes state management and plan output self-documenting.
- Using `for_each` instead of `count` means resources are tracked by key (stable), not by index (fragile — removing an element shifts all subsequent indexes).

### Verify with State Commands

```bash
terraform state list
```

Expected output:

```bash
aws_subnet.list_subnet["dev"]
aws_subnet.list_subnet["prod"]
```

### Inspect Resources with `terraform console`

```bash
terraform console
> aws_subnet.list_subnet
```

Expected output (abbreviated):

```bash
{
  "dev" = {
    "arn" = "arn:aws:ec2:us-east-1:1234567890:subnet/subnet-052d26040d4b91a51"
    "assign_ipv6_address_on_creation" = false
    ...
  }
  "prod" = { ... }
}
```

```bash
# Line-by-line Comments
terraform console                  # opens an interactive REPL for evaluating Terraform expressions
> aws_subnet.list_subnet           # evaluates the entire for_each resource; returns a map of objects keyed by each.key
# Use CTRL-C to exit the console
```

## Task 4: Map of Maps for Per-Environment Configuration

A flat map limits each key to a single value. A **map of maps** (`map(any)`) allows multiple attributes per key, enabling unique settings per environment in one variable.

### Variable Declaration

```hcl
variable "env" {
  type = map(any)
  default = {
    prod = {
      ip = "10.0.150.0/24"
      az = "us-east-1a"
    }
    dev = {
      ip = "10.0.250.0/24"
      az = "us-east-1e"
    }
  }
}
```

```hcl
# Line-by-line Comments
variable "env" {
  type = map(any)       # map whose values are objects (any type); enables nested attribute access
  default = {
    prod = {            # key "prod" maps to an object with two attributes
      ip = "10.0.150.0/24"  # CIDR block for prod
      az = "us-east-1a"     # availability zone for prod
    }
    dev = {             # key "dev" maps to an object with two attributes
      ip = "10.0.250.0/24"  # CIDR block for dev
      az = "us-east-1e"     # availability zone for dev — different from prod
    }
  }
}
```

### Updated Resource Block

```hcl
resource "aws_subnet" "list_subnet" {
  for_each          = var.env
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = each.value.ip
  availability_zone = each.value.az
}
```

```hcl
# Line-by-line Comments
resource "aws_subnet" "list_subnet" {
  for_each          = var.env        # iterates over the map of maps
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = each.value.ip  # accesses the "ip" attribute of the current key's object
  availability_zone = each.value.az  # accesses the "az" attribute of the current key's object
}
```

**Code Walkthrough:**

- `each.value` is the nested object (`{ ip = "...", az = "..." }`). Dot notation accesses individual attributes within it.
- Each environment now has an independent availability zone, which was not possible with the flat `map(string)` from Task 3.
- Running `terraform plan` shows only the `dev` subnet is replaced (AZ changes from `us-east-1a` to `us-east-1e`); `prod` remains unchanged.

```bash
terraform apply -auto-approve
```

## Key Terms & Definitions

| Term                    | Definition                                                                                                       |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **`list(type)`**        | An ordered collection of same-typed values; elements accessed by zero-based integer index                        |
| **`map(type)`**         | An unordered collection of key/value pairs where all values share the same type; elements accessed by string key |
| **`map(any)`**          | A map whose values may be objects (nested maps); enables grouping multiple attributes per key                    |
| **`tuple`**             | An ordered collection that allows mixed types; similar to a list but without the type constraint                 |
| **`object`**            | A structural type with named attributes, each potentially of a different type                                    |
| **Index access**        | Syntax `var.list_var[N]` to select the Nth element (zero-based) from a list                                      |
| **Key access**          | Syntax `var.map_var["key"]` or `var.map_var[var.other]` to select a value by key from a map                      |
| **`for_each`**          | Meta-argument that instructs Terraform to create one resource instance per element in a map or set               |
| **`each.key`**          | Within a `for_each` block, the current iteration's key string                                                    |
| **`each.value`**        | Within a `for_each` block, the current iteration's value (may be a string, object, etc.)                         |
| **`terraform console`** | Interactive REPL for evaluating Terraform expressions against the current state                                  |

---

## Common Exam Traps

- **Lists are zero-indexed.** `var.list[0]` is the first element, `var.list[1]` is the second. Off-by-one errors are a common mistake.
- **Passing a list where a string is expected causes a plan error.** Always index into a list (`var.list[0]`) when the receiving argument expects a scalar string.
- **`for_each` tracks resources by key, not by position.** This is why `for_each` over a map is preferred over `count` for named resources — removing a key destroys only that resource, not all resources at higher indexes.
- **`each.key` and `each.value` are only available inside a `for_each` resource block.** They are not available inside `count`-based resources.
- **`map(any)` is required for maps of objects.** `map(string)` only allows string values. If the map values are objects (nested maps), declare the type as `map(any)` or `map(object({...}))`.
- **`terraform console` reads current state.** Results reflect the last applied state, not the pending plan. Use it for inspecting current resource attributes, not future planned values.
- **Resource addresses change when switching from `count` to `for_each`.** Switching from `aws_subnet.list_subnet[0]` (count) to `aws_subnet.list_subnet["dev"]` (for_each) causes Terraform to destroy and recreate the resource because the address changed.
