# Terraform Built-In Functions

## Overview

Terraform provides a large library of built-in functions that can be used within expressions to transform, combine, and manipulate data. Functions operate on the full range of Terraform value types — numbers, strings, collections, IP addresses, and more — and are used inside `locals` blocks, resource arguments, outputs, and anywhere else an expression is valid. This lab demonstrates numeric, string, and IP network functions through hands-on tasks.

---

## Concepts

### Function Categories

| Category            | Examples                                                           | Common Use Cases                                 |
| ------------------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| **Numeric**         | `max()`, `min()`, `abs()`, `ceil()`, `floor()`                     | Select highest/lowest value, round numbers       |
| **String**          | `upper()`, `lower()`, `format()`, `join()`, `split()`, `trim()`    | Standardize tags, generate names, parse strings  |
| **Collection**      | `length()`, `contains()`, `tolist()`, `toset()`, `tomap()`         | List/map manipulation, type conversion           |
| **Encoding**        | `jsonencode()`, `jsondecode()`, `base64encode()`, `base64decode()` | Serialize policy documents, decode API responses |
| **Filesystem**      | `file()`, `filebase64()`                                           | Read local file contents into configuration      |
| **Date & Time**     | `timestamp()`, `formatdate()`                                      | Stamp resources with creation time               |
| **Hash & Crypto**   | `md5()`, `sha256()`, `bcrypt()`                                    | Generate checksums, hash secrets                 |
| **IP Network**      | `cidrsubnet()`, `cidrhost()`, `cidrnetmask()`                      | Calculate subnet CIDRs from a parent block       |
| **Type Conversion** | `tostring()`, `tonumber()`, `tobool()`                             | Explicit type coercion between primitives        |

- Functions are evaluated at plan time; they cannot reference values that are only known after `apply`.
- Functions can be nested: `lower(join("-", [local.application, data.aws_region.current.name]))`.
- Use `terraform console` to interactively test function expressions before adding them to configuration.

### Variable Declarations

```hcl
variable "num_1" {
  type        = number
  description = "Numbers for function labs"
  default     = 88
}

variable "num_2" {
  type        = number
  description = "Numbers for function labs"
  default     = 73
}

variable "num_3" {
  type        = number
  description = "Numbers for function labs"
  default     = 52
}
```

```hcl
# Line-by-line Comments
variable "num_1" {
  type        = number   # restricts input to numeric values (integer or decimal)
  description = "Numbers for function labs"
  default     = 88       # used as the input for max/min examples
}
# num_2 default = 73, num_3 default = 52 — same structure
```

### Locals and Outputs

```hcl
locals {
  maximum = max(var.num_1, var.num_2, var.num_3)
  minimum = min(var.num_1, var.num_2, var.num_3, 44, 20)
}

output "max_value" {
  value = local.maximum
}

output "min_value" {
  value = local.minimum
}
```

```hcl
# Line-by-line Comments
locals {
  maximum = max(var.num_1, var.num_2, var.num_3)
  # max() — returns the highest value from an arbitrary number of arguments
  # result: max(88, 73, 52) = 88

  minimum = min(var.num_1, var.num_2, var.num_3, 44, 20)
  # min() — returns the lowest value; accepts both variables and literal numbers
  # result: min(88, 73, 52, 44, 20) = 20
}

output "max_value" {
  value = local.maximum   # displays 88
}

output "min_value" {
  value = local.minimum   # displays 20
}
```

**Code Walkthrough:**

- `max()` and `min()` accept any number of arguments of type `number` — variables, literals, or expressions can be mixed freely.
- Encapsulating the function call inside a `local` avoids repeating the expression if the value is needed in multiple places.
- No infrastructure changes occur; running `terraform apply -auto-approve` only updates outputs in state.

```bash
terraform apply -auto-approve
# Expected outputs:
# max_value = 88
# min_value = 20
```

## Task 2: String Functions

### 2a — `upper()` on Resource Tags

```hcl
resource "aws_vpc" "vpc" {
  cidr_block = var.vpc_cidr

  tags = {
    Name        = upper(var.vpc_name)
    Environment = upper(var.environment)
    Terraform   = upper("true")
  }

  enable_dns_hostnames = true
}
```

```hcl
# Line-by-line Comments
tags = {
  Name        = upper(var.vpc_name)    # converts vpc_name to UPPERCASE regardless of input case
  Environment = upper(var.environment) # converts environment to UPPERCASE
  Terraform   = upper("true")          # literal "true" → "TRUE"
}
```

**Code Walkthrough:**

- `upper(string)` converts every character in the string to its uppercase equivalent.
- `lower(string)` is the inverse — converts to all lowercase.
- Applying `upper()` or `lower()` directly inside a resource block enforces tag casing standards without requiring variable validation or operator discipline.

```bash
terraform apply -auto-approve
# Tags update: "demo_vpc" → "DEMO_VPC", "dev" → "DEV", "true" → "TRUE"
```

### 2b — `lower()` on All Common Tags

Apply `lower()` to every value in the `common_tags` locals to enforce an all-lowercase standard without validation errors.

```hcl
locals {
  common_tags = {
    Name      = lower(local.server_name)
    Owner     = lower(local.team)
    App       = lower(local.application)
    Service   = lower(local.service_name)
    AppTeam   = lower(local.app_team)
    CreatedBy = lower(local.createdby)
  }
}
```

```hcl
# Line-by-line Comments
locals {
  common_tags = {
    Name      = lower(local.server_name)   # silently normalizes any input to lowercase
    Owner     = lower(local.team)          # e.g., "CloudTeam" → "cloudteam"
    App       = lower(local.application)
    Service   = lower(local.service_name)
    AppTeam   = lower(local.app_team)      # "CloudTeam" (capital C, T) → "cloudteam"
    CreatedBy = lower(local.createdby)
  }
}
```

**Code Walkthrough:**

- Wrapping every tag value in `lower()` is a defensive coding pattern: it absorbs any user-supplied mixed-case values transparently.
- This is preferable to `validation` blocks in shared modules because it corrects the input silently rather than rejecting it with an error.
- In the lab, the only observed tag change was `AppTeam` from `"CloudTeam"` (capital C and T) to `"cloudteam"`.

**Prerequisite:** Set a mixed-case environment variable to test normalization:

```hcl
# terraform.auto.tfvars
environment = "PROD_Environment"
```

```bash
terraform plan    # observe tag updates
terraform apply -auto-approve
```

### 2c — `join()` for Dynamic Name Generation

```hcl
locals {
  common_tags = {
    Name = join("-",
      [local.application,
        data.aws_region.current.name,
      local.createdby])
    Owner     = lower(local.team)
    App       = lower(local.application)
    Service   = lower(local.service_name)
    AppTeam   = lower(local.app_team)
    CreatedBy = lower(local.createdby)
  }
}
```

```hcl
# Line-by-line Comments
Name = join("-",
  [local.application,             # first element: application name
    data.aws_region.current.name, # second element: current AWS region (from data source)
  local.createdby])               # third element: creator identifier
# join(separator, list) — concatenates all list elements with the separator between them
# result example: "myapp-us-east-1-terraform"
```

**Code Walkthrough:**

- `join(separator, list)` takes a delimiter string and a list of strings, returning a single concatenated string.
- Using a data source attribute (`data.aws_region.current.name`) as one of the join elements means the `Name` tag is computed at plan time from live data — no hardcoded region string needed.
- This pattern makes modules fully reusable across regions without any variable changes.

```bash
terraform plan    # observe the dynamically generated Name tag value
terraform apply -auto-approve
```

## Task 3: `cidrsubnet()` IP Network Function

The `cidrsubnet()` function has been used since the first `terraform apply` in this course to create subnet CIDR blocks automatically from the VPC CIDR.

### Existing Usage in the Configuration

```hcl
resource "aws_subnet" "private_subnets" {
  for_each          = var.private_subnets
  vpc_id            = aws_vpc.vpc.id
  cidr_block        = cidrsubnet(var.vpc_cidr, 8, each.value)
  availability_zone = tolist(data.aws_availability_zones.available.names)[each.value]

  tags = {
    Name      = each.key
    Terraform = "true"
  }
}
```

```hcl
# Line-by-line Comments
resource "aws_subnet" "private_subnets" {
  for_each = var.private_subnets         # iterates over the private_subnets map (keys = names, values = integers)
  vpc_id   = aws_vpc.vpc.id

  cidr_block = cidrsubnet(var.vpc_cidr, 8, each.value)
  # cidrsubnet(prefix, newbits, netnum)
  # var.vpc_cidr  — the parent CIDR block, e.g. "10.0.0.0/16"
  # 8             — number of additional bits to add to the prefix; /16 + 8 = /24
  # each.value    — the subnet number (e.g., 1, 2, 3); selects the Nth /24 within the /16
  # result:       — each.value=1 → "10.0.1.0/24", each.value=2 → "10.0.2.0/24", etc.

  availability_zone = tolist(data.aws_availability_zones.available.names)[each.value]
  # tolist() — converts the set returned by the data source to an ordered list (required for index access)
  # [each.value] — selects the AZ at index matching the subnet number
}
```

**Code Walkthrough:**

`cidrsubnet(prefix, newbits, netnum)` has three parameters:

| Parameter | Description                                                            | Example Value     |
| --------- | ---------------------------------------------------------------------- | ----------------- |
| `prefix`  | Parent CIDR block in notation                                          | `"10.0.0.0/16"`   |
| `newbits` | Number of additional bits to add to the prefix length                  | `8` (gives `/24`) |
| `netnum`  | The whole-number index selecting which subnet within the address space | `1`, `2`, `3`     |

- With `prefix = "10.0.0.0/16"` and `newbits = 8`, each resulting subnet is a `/24`.
- `netnum = 1` → `10.0.1.0/24`, `netnum = 2` → `10.0.2.0/24`, and so on.
- For **public subnets**, the same function is used but `each.value + 100` is passed as `netnum`, producing `10.0.101.0/24`, `10.0.102.0/24`, `10.0.103.0/24` — ensuring no overlap with private subnets.
- `tolist()` is required because `data.aws_availability_zones.available.names` returns a `set`, which is unordered and cannot be indexed directly.

## Key Terms & Definitions

| Term                                      | Definition                                                                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **Built-in Function**                     | A predefined expression transformer in HCL — HashiCorp Configuration Language — that accepts arguments and returns a computed value |
| **`max(n, ...)`**                         | Returns the largest value from the provided numeric arguments                                                                       |
| **`min(n, ...)`**                         | Returns the smallest value from the provided numeric arguments                                                                      |
| **`upper(string)`**                       | Converts all characters in a string to uppercase                                                                                    |
| **`lower(string)`**                       | Converts all characters in a string to lowercase                                                                                    |
| **`join(separator, list)`**               | Concatenates a list of strings using the specified separator                                                                        |
| **`cidrsubnet(prefix, newbits, netnum)`** | Calculates a subnet CIDR block from a parent prefix by adding bits and selecting an index                                           |
| **`tolist(set)`**                         | Converts a Terraform `set` to an ordered `list`, enabling index-based access                                                        |
| **`terraform console`**                   | Interactive REPL for testing Terraform expressions and function calls against current state                                         |

## Common Exam Traps

- **Functions cannot be used as variable defaults.** The `default` argument in a `variable` block must be a literal value. Function calls are only valid inside expressions in `locals`, resource arguments, and outputs.
- **`cidrsubnet` newbits is additive, not absolute.** If the parent prefix is `/16` and `newbits = 8`, the result is `/24` (16 + 8), not `/8`.
- **`tolist()` is required before indexing a `set`.** Data sources like `aws_availability_zones` return a `set(string)`, which is unordered and cannot be accessed by index. Always convert with `tolist()` first.
- **`join()` requires a list, not separate arguments.** `join("-", "a", "b")` is incorrect; the correct form is `join("-", ["a", "b"])`.
- **`upper()` and `lower()` affect the entire string.** They do not perform selective capitalization (e.g., title case). Use `format()` or string concatenation for more complex casing requirements.
- **Functions are evaluated at plan time.** Any function that depends on a value not yet known (e.g., a resource ID that will only exist after `apply`) will produce `(known after apply)` in the plan output rather than a computed result.
