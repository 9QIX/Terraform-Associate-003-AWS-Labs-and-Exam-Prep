# Terraform Outputs

## Overview

Terraform generates extensive metadata after each operation. Rather than parsing all of it with `terraform show`, output values let operators declare exactly which attributes to surface — IP addresses, resource ARNs, VPC IDs, and more. Outputs are also consumed as inputs by child modules or downstream Terraform configurations.

---

## Concepts

- An **output block** declares a named value to be displayed after `terraform apply` and queryable via `terraform output`.
- Outputs are written to the **Terraform state file**; they persist between runs.
- The `sensitive = true` argument suppresses a value in CLI output but does **not** remove it from the state file.
- Outputs can be used as cross-module data transfer (a child module's output becomes an input variable in a parent or sibling module).

### Output Block Parameters

| Parameter     | Required | Description                                                             |
| ------------- | -------- | ----------------------------------------------------------------------- |
| `value`       | Yes      | The expression whose result is exported                                 |
| `description` | No       | Human-readable explanation (not shown in CLI output)                    |
| `sensitive`   | No       | When `true`, masks the value in terminal output; still visible in state |

---

## Terraform Workflow

### Task Flow

1. Add or modify `output` blocks in `outputs.tf`.
2. Run `terraform apply -auto-approve` (if no infrastructure changes, only output values update).
3. Use `terraform output` to query values without re-running an apply.
4. Mark sensitive values with `sensitive = true` to suppress CLI display.

---

## Task 1: Create Output Values

### Configuration

```hcl
output "public_ip" {
  description = "This is the public IP of my web server"
  value       = aws_instance.web_server.public_ip
}
```

```hcl
# Line-by-line Comments
output "public_ip" {                                        # declares an output named "public_ip"
  description = "This is the public IP of my web server"  # informational only; not displayed in CLI
  value       = aws_instance.web_server.public_ip          # references the public_ip attribute of the aws_instance resource
}
```

**Code Walkthrough:**

- `aws_instance.web_server` is the resource address; `public_ip` is one of its exported attributes.
- `description` is optional but recommended for documentation — it does not appear in `terraform apply` or `terraform output` output.
- After applying, Terraform writes this output to state and displays it at the end of the apply run.

### Apply Command

```bash
terraform apply -auto-approve
```

```bash
# Line-by-line Comments
terraform apply        # executes the plan and modifies infrastructure
  -auto-approve        # skips the interactive "yes" confirmation prompt
```

**Expected CLI output (no infrastructure changes, only output values updated):**

```text
Apply complete! Resources: 0 added, 0 changed, 0 destroyed.

Outputs:

hello-world      = "Hello World"
public_ip        = "44.200.207.151"
public_url       = "https://10.0.101.169:8080/index.html"
vpc_id           = "vpc-0dcd2b053088ea107"
vpc_information  = "Your demo_environment VPC has an ID of vpc-0dcd2b053088ea107"
```

> Note: `description` is not shown in CLI output — only the output name and its value are displayed.

## Task 2: Query Outputs with `terraform output`

### List All Outputs

```bash
terraform output
```

```bash
# Line-by-line Comments
terraform output   # prints all declared output names and their current values from state
```

### Query a Specific Output

```bash
terraform output public_ip
```

```bash
# Line-by-line Comments
terraform output public_ip   # retrieves and prints the value of the named output only
```

### Use Output in a Shell Command (Raw Mode)

```bash
ping $(terraform output -raw public_ip)
```

```bash
# Line-by-line Comments
ping                              # sends ICMP echo requests to the target
$(...)                            # shell command substitution — runs the inner command and passes its output as an argument
terraform output -raw public_ip   # returns the output value without surrounding quotes, suitable for shell use
```

**Code Walkthrough:**

- `terraform output -raw <name>` strips the surrounding quotes that `terraform output <name>` normally includes, making the value safe to pass directly to other shell commands.
- In this example, the ping will likely time out because the security group does not allow inbound ICMP traffic — this is expected behavior.
- This pattern is useful for scripting: automating DNS updates, health checks, or passing infrastructure values to external tools.

## Task 3: Suppress Sensitive Output Values

### Configuration

```hcl
output "ec2_instance_arn" {
  value     = aws_instance.web_server.arn
  sensitive = true
}
```

```hcl
# Line-by-line Comments
output "ec2_instance_arn" {              # declares an output named "ec2_instance_arn"
  value     = aws_instance.web_server.arn # references the ARN attribute of the EC2 instance
  sensitive = true                        # masks the value in CLI output; still stored in state
}
```

**Code Walkthrough:**

- An ARN (Amazon Resource Name) includes the AWS account number, which is considered sensitive information.
- Setting `sensitive = true` causes Terraform to display `<sensitive>` in place of the actual value during `terraform apply` and `terraform output` listing.
- The value **is still written to the state file** in plaintext — `sensitive = true` is a display-only control, not an encryption or access control mechanism.
- To retrieve the actual value when needed, run `terraform output ec2_instance_arn` directly — Terraform will reveal it upon explicit query.

### Apply Output with Sensitive Value

```text
Apply complete! Resources: 0 added, 0 changed, 0 destroyed.

Outputs:

ec2_instance_arn = <sensitive>
hello-world      = "Hello World"
public_ip        = "44.200.207.151"
public_url       = "https://10.0.101.169:8080/index.html"
vpc_id           = "vpc-0dcd2b053088ea107"
vpc_information  = "Your demo_environment VPC has an ID of vpc-0dcd2b053088ea107"
```

### Explicitly Revealing a Sensitive Output

```bash
terraform output ec2_instance_arn
```

This will print the actual ARN value, including the embedded account number.

## Key Terms & Definitions

| Term                   | Definition                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Output Block**       | HCL — HashiCorp Configuration Language block that declares a named value to be exported after `terraform apply`                 |
| **`terraform output`** | CLI command that queries output values stored in the Terraform state file without triggering a new apply                        |
| **`-raw` flag**        | Modifier for `terraform output` that prints the value without surrounding quotes, for use in shell scripting                    |
| **`sensitive = true`** | Output argument that masks the value in terminal output; the value remains in the state file                                    |
| **ARN**                | Amazon Resource Name — a globally unique identifier for AWS resources that includes the account number, region, and resource ID |
| **`-auto-approve`**    | `terraform apply` flag that skips the interactive confirmation prompt                                                           |
| **State File**         | The `terraform.tfstate` file that records the current known state of managed infrastructure, including all output values        |

---

## Common Exam Traps

- **`sensitive = true` does NOT encrypt or remove the value from state.** It only suppresses display in the CLI. The state file stores the value in plaintext — protect state file access separately.
- **`description` is not shown in CLI output.** It is metadata for human readers of the configuration, not a runtime display field.
- **`terraform output <name>` bypasses the sensitive mask.** Explicitly querying a sensitive output by name will reveal its value — the suppression only applies to bulk listing during `apply` and `terraform output` (no arguments).
- **Outputs require an apply to update.** Adding a new output block and running only `terraform plan` will not persist the output to state — an `apply` is required.
- **`-raw` vs. quoted output.** Without `-raw`, `terraform output public_ip` returns `"44.200.207.151"` (with quotes). With `-raw`, it returns `44.200.207.151` — essential when passing values to other shell commands to avoid quote injection issues.
- **Outputs as module return values.** In a module context, outputs are the only mechanism by which a child module exposes values to its caller. A resource attribute inside a module is not directly accessible from outside without a corresponding output block.
