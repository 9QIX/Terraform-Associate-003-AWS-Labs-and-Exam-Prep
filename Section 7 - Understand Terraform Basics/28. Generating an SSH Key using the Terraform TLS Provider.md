# Generating an SSH Key using the Terraform TLS Provider

## Overview

The Terraform TLS provider enables creation and management of Transport Layer Security (TLS) keys and certificates as part of infrastructure deployments. This utility provider generates cryptographic materials including private keys, public keys, and certificates without requiring external tools. This lab demonstrates generating an RSA private key using the TLS provider and saving it locally using the Local provider for future authentication with EC2 instances.

---

## Concepts

### TLS Provider

**Purpose:**

- Generate private keys (RSA, ECDSA, ED25519)
- Create self-signed certificates
- Generate certificate signing requests (CSRs)
- Manage TLS/SSL cryptographic materials
- Utility provider (no external service interaction)

**Use Cases:**

- SSH key generation for instance authentication
- Development/testing certificates
- Certificate rotation automation
- Cryptographic material management

**Security Note:**

- Self-signed certificates suitable for development only
- NOT recommended for production services
- Use proper Certificate Authorities (CAs) for production

### Provider Combination

**TLS + Local Providers:**

- TLS provider generates cryptographic materials
- Local provider saves materials to filesystem
- Combined workflow for key management
- Demonstrates multi-provider integration

### Task 3: Generate SSH Key with TLS Provider

**Add to `main.tf`:**

```hcl
resource "tls_private_key" "generated" {
  algorithm = "RSA"
}

resource "local_file" "private_key_pem" {
  content  = tls_private_key.generated.private_key_pem
  filename = "MyAWSKey.pem"
}
```

**Line-by-line Comments:**

```hcl
resource "tls_private_key" "generated" {  # TLS private key resource
  algorithm = "RSA"                       # RSA algorithm selection
}

resource "local_file" "private_key_pem" {           # Local file resource
  content  = tls_private_key.generated.private_key_pem  # Private key content
  filename = "MyAWSKey.pem"                         # Output filename
}
```

**Code Walkthrough:**

- **tls_private_key Resource:**

  - Generates RSA private key
  - `algorithm = "RSA"` specifies key type
  - Other options: ECDSA, ED25519
  - Default RSA key size: 2048 bits
  - Exports multiple attributes: `private_key_pem`, `public_key_openssh`, `public_key_pem`

- **local_file Resource:**
  - Creates file on local filesystem
  - `content` references TLS resource output
  - `tls_private_key.generated.private_key_pem` retrieves private key in PEM format
  - `filename` specifies output path (relative to working directory)
  - File created with default permissions (needs chmod for SSH use)

## Providers & Resources

### TLS Provider Resources

**Available Resources:**

| Resource                  | Purpose                                     |
| ------------------------- | ------------------------------------------- |
| `tls_private_key`         | Generate private keys (RSA, ECDSA, ED25519) |
| `tls_self_signed_cert`    | Create self-signed certificates             |
| `tls_locally_signed_cert` | Sign certificates with local CA             |
| `tls_cert_request`        | Generate certificate signing requests       |

### tls_private_key Attributes

**Exported Attributes:**

| Attribute                    | Description                  | Use Case                        |
| ---------------------------- | ---------------------------- | ------------------------------- |
| `private_key_pem`            | Private key in PEM format    | SSH authentication, TLS servers |
| `public_key_pem`             | Public key in PEM format     | Certificate generation          |
| `public_key_openssh`         | Public key in OpenSSH format | SSH authorized_keys             |
| `public_key_fingerprint_md5` | MD5 fingerprint              | Key verification                |
| `id`                         | Resource identifier          | Terraform tracking              |

### Algorithm Options

**Supported Algorithms:**

```hcl
# RSA (default 2048 bits)
resource "tls_private_key" "rsa" {
  algorithm = "RSA"
  rsa_bits  = 4096  # Optional: 2048, 3072, 4096
}

# ECDSA
resource "tls_private_key" "ecdsa" {
  algorithm   = "ECDSA"
  ecdsa_curve = "P384"  # P224, P256, P384, P521
}

# ED25519 (modern, recommended)
resource "tls_private_key" "ed25519" {
  algorithm = "ED25519"
}
```

### Using Public Key with AWS

**Complete Example:**

```hcl
resource "tls_private_key" "generated" {
  algorithm = "RSA"
}

resource "local_file" "private_key_pem" {
  content  = tls_private_key.generated.private_key_pem
  filename = "MyAWSKey.pem"
}

resource "aws_key_pair" "generated" {
  key_name   = "MyAWSKey"
  public_key = tls_private_key.generated.public_key_openssh
}

resource "aws_instance" "web" {
  ami           = "ami-12345678"
  instance_type = "t3.micro"
  key_name      = aws_key_pair.generated.key_name
}
```

**Code Walkthrough:**

- TLS provider generates key pair
- Local provider saves private key
- AWS provider uploads public key
- EC2 instance uses key pair for SSH access
- Complete workflow for SSH authentication

## Pitfalls & Best Practices

### Best Practices

**Use ED25519 for Modern Systems:**

```hcl
resource "tls_private_key" "modern" {
  algorithm = "ED25519"
}
```

- Smaller key size (256 bits)
- Faster generation and verification
- More secure than RSA 2048
- Supported by modern SSH clients

**Set Proper File Permissions:**

```hcl
resource "local_file" "private_key_pem" {
  content         = tls_private_key.generated.private_key_pem
  filename        = "MyAWSKey.pem"
  file_permission = "0600"  # Owner read/write only
}
```

- SSH requires restrictive permissions
- `0600` prevents "permissions too open" error
- Protects private key from unauthorized access

**Use for Development Only:**

- TLS provider suitable for testing/development
- NOT recommended for production
- Use proper key management systems (KMS, Vault) for production
- Rotate keys regularly

**Store Keys Securely:**

- Add `*.pem` to `.gitignore`
- Never commit private keys to version control
- Use secret management for production keys
- Consider using `sensitive = true` for outputs

**Separate Key Generation from Infrastructure:**

```hcl
# Separate configuration for key generation
# keys.tf
resource "tls_private_key" "generated" {
  algorithm = "RSA"
}

# main.tf references key
resource "aws_key_pair" "generated" {
  key_name   = "MyAWSKey"
  public_key = tls_private_key.generated.public_key_openssh
}
```

### Common Pitfalls

**Incorrect File Permissions:**

```bash
# Error: Permissions 0777 for 'MyAWSKey.pem' are too open
ssh -i MyAWSKey.pem user@host
```

- SSH rejects keys with overly permissive permissions
- Fix: `chmod 600 MyAWSKey.pem`
- Or set `file_permission = "0600"` in Terraform

**Committing Private Keys:**

- Private keys in version control = security breach
- Add to `.gitignore` immediately
- Rotate keys if accidentally committed
- Use git history rewriting to remove

**Using Self-Signed Certs in Production:**

- Self-signed certificates not trusted by browsers
- Use Let's Encrypt or commercial CAs for production
- TLS provider suitable for internal/development only

**Not Backing Up Keys:**

- Losing private key = losing access to instances
- Back up keys securely
- Consider key rotation strategy
- Document key locations

**Hardcoding Filenames:**

```hcl
# Bad: Hardcoded filename
filename = "MyAWSKey.pem"

# Good: Variable-based filename
filename = "${var.environment}-key.pem"
```

- Use variables for flexibility
- Enables multi-environment deployments
- Prevents filename conflicts

**Forgetting Key Pair Upload:**

```hcl
# Incomplete: Key generated but not uploaded to AWS
resource "tls_private_key" "generated" {
  algorithm = "RSA"
}

# Complete: Key uploaded to AWS
resource "aws_key_pair" "generated" {
  key_name   = "MyAWSKey"
  public_key = tls_private_key.generated.public_key_openssh
}
```

- Generate key AND upload public key to AWS
- EC2 instances require key pair in AWS

## Key Terms & Definitions

| Term                        | Definition                                                            |
| --------------------------- | --------------------------------------------------------------------- |
| **TLS Provider**            | Terraform utility provider for generating cryptographic materials     |
| **Private Key**             | Secret key used for authentication and decryption                     |
| **Public Key**              | Publicly shareable key for encryption and verification                |
| **PEM Format**              | Privacy-Enhanced Mail format for encoding keys and certificates       |
| **OpenSSH Format**          | Public key format used by SSH for authorized_keys                     |
| **RSA**                     | Rivest-Shamir-Adleman asymmetric encryption algorithm                 |
| **ED25519**                 | Modern elliptic curve signature algorithm                             |
| **Self-Signed Certificate** | Certificate signed by its own private key (not trusted CA)            |
| **Key Pair**                | Combination of private and public keys                                |
| **Utility Provider**        | Provider that performs operations without managing external resources |

## Common Exam Traps

1. **TLS Provider Category**

   - TLS is a utility provider
   - Does not manage external infrastructure
   - Performs cryptographic operations locally

2. **Private Key Security**

   - Private keys are sensitive data
   - Should never be committed to version control
   - Marked as `(sensitive value)` in Terraform output

3. **File Permissions**

   - SSH requires private key permissions of 0600
   - Default local_file permissions may be too open
   - Set `file_permission = "0600"` explicitly

4. **Algorithm Options**

   - RSA: Traditional, widely supported
   - ECDSA: Elliptic curve, smaller keys
   - ED25519: Modern, recommended for new deployments

5. **Public vs. Private Key Usage**

   - Private key: Keep secret, use for authentication
   - Public key: Share freely, upload to AWS
   - `public_key_openssh` for AWS key pairs

6. **Production Usage**

   - TLS provider suitable for development/testing
   - NOT recommended for production
   - Use proper key management systems

7. **Resource Dependencies**

   - `local_file` depends on `tls_private_key`
   - Terraform handles implicit dependencies
   - Private key generated before file written

8. **Key Rotation**

   - Changing algorithm or regenerating key replaces resource
   - Causes instance recreation if key_name changes
   - Plan carefully for key rotation

9. **Multiple Providers Required**

   - TLS provider generates key
   - Local provider saves key to file
   - AWS provider uploads public key
   - Demonstrates multi-provider workflow

10. **Sensitive Data Handling**
    - Private key content marked sensitive
    - Not displayed in plan/apply output
    - Still stored in state file (secure state storage required)

## Updated Information (as of 2025-01-XX)

### Current TLS Provider Version

- **Lab demonstrates**: TLS provider 3.1.0
- **Current version**: TLS provider 4.0.x (as of January 2025)
- **Recommendation**: Update to `version = "~> 4.0"`
- **Breaking changes**: TLS 4.0 introduced new attributes and deprecated some legacy options
- Review [TLS Provider Changelog](https://github.com/hashicorp/terraform-provider-tls/blob/main/CHANGELOG.md)

### Algorithm Recommendations

- **Lab uses**: RSA algorithm
- **Current best practice**: Use ED25519 for new deployments
  ```hcl
  resource "tls_private_key" "generated" {
    algorithm = "ED25519"
  }
  ```
- ED25519 offers better security and performance
- RSA still widely supported for compatibility

### File Permissions Best Practice

- **Lab shows**: Default permissions (0777)
- **Current recommendation**: Explicitly set restrictive permissions
  ```hcl
  resource "local_file" "private_key_pem" {
    content         = tls_private_key.generated.private_key_pem
    filename        = "MyAWSKey.pem"
    file_permission = "0600"
  }
  ```
- Prevents SSH "permissions too open" errors
- Improves security posture

### Sensitive Data Handling

- **Current Terraform**: Automatically marks private keys as sensitive
- **State file security**: Use encrypted remote backends
- **Recommendation**: Use AWS Secrets Manager or HashiCorp Vault for production keys

### Local Provider Version

- **Lab demonstrates**: Local provider 2.1.0
- **Current version**: Local provider 2.5.x
- **Recommendation**: Update to `version = "~> 2.5"`

### Production Key Management

- **Modern approach**: Use cloud-native key management
  - AWS KMS for key generation
  - AWS Systems Manager Parameter Store for storage
  - HashiCorp Vault for enterprise key management
- TLS provider remains suitable for development/testing only

### Key Rotation Strategy

- **Best practice**: Implement automated key rotation
- Use Terraform to manage key lifecycle
- Document key rotation procedures
- Test rotation in non-production first
