# Terraform Provisioners

## Overview

Terraform provisioners execute scripts or commands on local or remote machines during resource creation or destruction. They enable post-deployment configuration, software installation, and service initialization. This lab demonstrates using `local-exec` and `remote-exec` provisioners to deploy a web application on an EC2 instance, including SSH key management, security group configuration, and remote command execution.

**Important**: Provisioners are a last resort. HashiCorp recommends using native provider features, configuration management tools (Ansible, Chef, Puppet), or cloud-init when possible.

---

## Concepts

### Provisioner Types

| Provisioner     | Execution Location              | Purpose                            | Common Use Cases                                      |
| --------------- | ------------------------------- | ---------------------------------- | ----------------------------------------------------- |
| **local-exec**  | Local machine running Terraform | Execute commands locally           | File permissions, local scripts, API calls            |
| **remote-exec** | Remote resource being created   | Execute commands on remote machine | Software installation, configuration, service startup |
| **file**        | Uploads to remote resource      | Copy files from local to remote    | Configuration files, scripts, certificates            |

### Provisioner Behavior

**Execution Timing:**

- Run after resource creation (default)
- Can run before resource destruction (`when = destroy`)
- Execute in order defined in configuration

**Failure Handling:**

- Default: Provisioner failure marks resource as "tainted"
- Tainted resources recreated on next apply
- Use `on_failure = continue` to ignore failures

### Connection Block

Required for `remote-exec` and `file` provisioners to authenticate to remote resources.

**Connection Types:**

- **SSH**: Linux/Unix instances
- **WinRM**: Windows instances

## Terraform Workflow

### Task 1: Create SSH Key Pair in AWS

```hcl
resource "aws_key_pair" "generated" {
  key_name   = "MyAWSKey"
  public_key = tls_private_key.generated.public_key_openssh

  lifecycle {
    ignore_changes = [key_name]
  }
}
```

**Line-by-line Comments:**

```hcl
resource "aws_key_pair" "generated" {                      # AWS key pair resource
  key_name   = "MyAWSKey"                                  # Key name in AWS
  public_key = tls_private_key.generated.public_key_openssh  # Public key from TLS provider

  lifecycle {                                              # Lifecycle configuration
    ignore_changes = [key_name]                            # Ignore key_name changes
  }
}
```

**Code Walkthrough:**

- References `tls_private_key` resource from previous lab
- Uploads public key to AWS
- `lifecycle.ignore_changes` prevents recreation if key_name modified
- Key pair enables SSH authentication to EC2 instances

**Apply Key Pair:**


### Task 2: Create Security Groups

**SSH Security Group:**

```hcl
resource "aws_security_group" "ingress-ssh" {
  name   = "allow-all-ssh"
  vpc_id = aws_vpc.vpc.id

  ingress {
    cidr_blocks = ["0.0.0.0/0"]
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

**Line-by-line Comments:**

```hcl
resource "aws_security_group" "ingress-ssh" {  # SSH security group
  name   = "allow-all-ssh"                     # Security group name
  vpc_id = aws_vpc.vpc.id                      # VPC association

  ingress {                                    # Inbound rules
    cidr_blocks = ["0.0.0.0/0"]                # Allow from anywhere (demo only!)
    from_port   = 22                           # SSH port
    to_port     = 22                           # SSH port
    protocol    = "tcp"                        # TCP protocol
  }

  egress {                                     # Outbound rules
    from_port   = 0                            # All ports
    to_port     = 0                            # All ports
    protocol    = "-1"                         # All protocols
    cidr_blocks = ["0.0.0.0/0"]                # Allow to anywhere
  }
}
```

**Code Walkthrough:**

- Allows SSH (port 22) from any IP (`0.0.0.0/0`)
- **Security Warning**: `0.0.0.0/0` is insecure for production
- Production: Restrict to specific IP ranges or bastion hosts
- Egress allows all outbound traffic

**Web Traffic Security Group:**

```hcl
resource "aws_security_group" "vpc-web" {
  name        = "vpc-web-${terraform.workspace}"
  vpc_id      = aws_vpc.vpc.id
  description = "Web Traffic"

  ingress {
    description = "Allow Port 80"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    description = "Allow Port 443"
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    description = "Allow all ip and ports outbound"
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

**Line-by-line Comments:**

```hcl
resource "aws_security_group" "vpc-web" {              # Web security group
  name        = "vpc-web-${terraform.workspace}"       # Workspace-specific name
  vpc_id      = aws_vpc.vpc.id                         # VPC association
  description = "Web Traffic"                          # Description

  ingress {                                            # HTTP rule
    description = "Allow Port 80"                      # Rule description
    from_port   = 80                                   # HTTP port
    to_port     = 80                                   # HTTP port
    protocol    = "tcp"                                # TCP protocol
    cidr_blocks = ["0.0.0.0/0"]                        # Allow from anywhere
  }

  ingress {                                            # HTTPS rule
    description = "Allow Port 443"                     # Rule description
    from_port   = 443                                  # HTTPS port
    to_port     = 443                                  # HTTPS port
    protocol    = "tcp"                                # TCP protocol
    cidr_blocks = ["0.0.0.0/0"]                        # Allow from anywhere
  }

  egress {                                             # Outbound rule
    description = "Allow all ip and ports outbound"    # Rule description
    from_port   = 0                                    # All ports
    to_port     = 0                                    # All ports
    protocol    = "-1"                                 # All protocols
    cidr_blocks = ["0.0.0.0/0"]                        # Allow to anywhere
  }
}
```

**Code Walkthrough:**

- Allows HTTP (80) and HTTPS (443) from anywhere
- `terraform.workspace` in name enables multi-environment deployments
- Permits all outbound traffic

### Task 3: Configure EC2 Instance with Connection Block

```hcl
resource "aws_instance" "ubuntu_server" {
  ami                         = data.aws_ami.ubuntu.id
  instance_type               = "t3.micro"
  subnet_id                   = aws_subnet.public_subnets["public_subnet_1"].id
  security_groups             = [
    aws_security_group.vpc-ping.id,
    aws_security_group.ingress-ssh.id,
    aws_security_group.vpc-web.id
  ]
  associate_public_ip_address = true
  key_name                    = aws_key_pair.generated.key_name

  connection {
    user        = "ubuntu"
    private_key = tls_private_key.generated.private_key_pem
    host        = self.public_ip
  }

  tags = {
    Name = "Ubuntu EC2 Server"
  }

  lifecycle {
    ignore_changes = [security_groups]
  }
}
```

**Line-by-line Comments:**

```hcl
resource "aws_instance" "ubuntu_server" {                  # EC2 instance resource
  ami                         = data.aws_ami.ubuntu.id     # Ubuntu AMI from data source
  instance_type               = "t3.micro"                 # Instance size
  subnet_id                   = aws_subnet.public_subnets["public_subnet_1"].id  # Public subnet
  security_groups             = [                          # Security groups list
    aws_security_group.vpc-ping.id,                        # ICMP security group
    aws_security_group.ingress-ssh.id,                     # SSH security group
    aws_security_group.vpc-web.id                          # Web security group
  ]
  associate_public_ip_address = true                       # Assign public IP
  key_name                    = aws_key_pair.generated.key_name  # SSH key pair

  connection {                                             # Connection configuration
    user        = "ubuntu"                                 # SSH username
    private_key = tls_private_key.generated.private_key_pem  # Private key for auth
    host        = self.public_ip                           # Connect to public IP
  }

  tags = {                                                 # Instance tags
    Name = "Ubuntu EC2 Server"                             # Instance name
  }

  lifecycle {                                              # Lifecycle rules
    ignore_changes = [security_groups]                     # Ignore SG changes
  }
}
```

**Code Walkthrough:**

- **security_groups**: Associates three security groups (ping, SSH, web)
- **key_name**: References AWS key pair for SSH access
- **connection block**: Defines how Terraform connects to instance
  - `user`: Default Ubuntu AMI username
  - `private_key`: Private key from TLS provider
  - `host = self.public_ip`: `self` refers to current resource
- **associate_public_ip_address**: Required for internet access
- **lifecycle.ignore_changes**: Prevents recreation if security groups modified externally

### Task 4: local-exec Provisioner

```hcl
resource "aws_instance" "ubuntu_server" {
  # ... previous configuration ...

  provisioner "local-exec" {
    command = "chmod 600 ${local_file.private_key_pem.filename}"
  }
}
```

**Line-by-line Comments:**

```hcl
  provisioner "local-exec" {                                   # Local execution provisioner
    command = "chmod 600 ${local_file.private_key_pem.filename}"  # Set key permissions
  }
```

**Code Walkthrough:**

- **local-exec**: Runs command on machine executing `terraform apply`
- **chmod 600**: Sets private key permissions (owner read/write only)
- SSH requires restrictive permissions on private keys
- References `local_file` resource filename
- Executes after instance creation

### Task 5: remote-exec Provisioner

```hcl
resource "aws_instance" "ubuntu_server" {
  # ... previous configuration ...

  provisioner "remote-exec" {
    inline = [
      "sudo rm -rf /tmp",
      "sudo git clone https://github.com/hashicorp/demo-terraform-101 /tmp",
      "sudo sh /tmp/assets/setup-web.sh",
    ]
  }
}
```

**Line-by-line Comments:**

```hcl
  provisioner "remote-exec" {                                      # Remote execution provisioner
    inline = [                                                     # List of commands
      "sudo rm -rf /tmp",                                          # Clean temp directory
      "sudo git clone https://github.com/hashicorp/demo-terraform-101 /tmp",  # Clone app
      "sudo sh /tmp/assets/setup-web.sh",                          # Run setup script
    ]
  }
```

**Code Walkthrough:**

- **remote-exec**: Executes commands on remote instance via SSH
- **inline**: List of commands executed sequentially
- Commands run after SSH connection established
- **Command 1**: Cleans `/tmp` directory
- **Command 2**: Clones web application from GitHub
- **Command 3**: Executes setup script to install/start web server
- Uses `connection` block for authentication
- Requires security group allowing SSH (port 22)

## Pitfalls & Best Practices

### Best Practices

**Use Provisioners as Last Resort:**

- Prefer native provider features (user_data, cloud-init)
- Use configuration management tools (Ansible, Chef, Puppet)
- Provisioners make resources less portable
- Difficult to test and debug

**Secure SSH Access:**

```hcl
# Bad: Allow SSH from anywhere
cidr_blocks = ["0.0.0.0/0"]

# Good: Restrict to specific IPs
cidr_blocks = ["203.0.113.0/24"]  # Your office IP range
```

**Handle Provisioner Failures:**

```hcl
provisioner "remote-exec" {
  inline = ["sudo apt-get update"]

  on_failure = continue  # Don't taint resource on failure
}
```

**Use Destroy Provisioners:**

```hcl
provisioner "remote-exec" {
  when = destroy
  inline = ["sudo systemctl stop webapp"]
}
```

**Separate Provisioner Logic:**

- Keep provisioner commands simple
- Use external scripts for complex logic
- Upload scripts with `file` provisioner

**Set Proper Key Permissions:**

```hcl
resource "local_file" "private_key_pem" {
  content         = tls_private_key.generated.private_key_pem
  filename        = "MyAWSKey.pem"
  file_permission = "0600"  # Set at creation
}
```

### Common Pitfalls

**Provisioner Placement:**

```hcl
# Wrong: Provisioner outside resource block
resource "aws_instance" "web" {
  ami = "ami-12345"
}
provisioner "remote-exec" {  # ERROR: Must be inside resource
  inline = ["echo hello"]
}

# Correct: Provisioner inside resource block
resource "aws_instance" "web" {
  ami = "ami-12345"

  provisioner "remote-exec" {
    inline = ["echo hello"]
  }
}
```

**Missing Connection Block:**

```hcl
# Wrong: remote-exec without connection
provisioner "remote-exec" {
  inline = ["echo hello"]  # ERROR: How to connect?
}

# Correct: Include connection block
connection {
  type        = "ssh"
  user        = "ubuntu"
  private_key = file("key.pem")
  host        = self.public_ip
}
provisioner "remote-exec" {
  inline = ["echo hello"]
}
```

**Incorrect self Reference:**

```hcl
# Wrong: Using wrong resource reference
host = aws_instance.web.public_ip  # May not work in connection block

# Correct: Use self
host = self.public_ip  # Refers to current resource
```

**Security Group Timing:**

- Security groups must allow SSH before provisioner runs
- Ensure security groups created/associated before instance
- Use `depends_on` if needed

**Provisioner Failures Taint Resources:**

- Failed provisioner marks resource as tainted
- Tainted resources recreated on next apply
- Use `on_failure = continue` to prevent tainting

**Hardcoded IP Addresses:**

```hcl
# Bad: Hardcoded IP
cidr_blocks = ["0.0.0.0/0"]

# Better: Use variables
cidr_blocks = [var.admin_ip_range]
```

**Not Testing SSH Connectivity:**

- Test SSH manually before using provisioners
- Verify security groups allow port 22
- Confirm key permissions (600)
- Check network connectivity

## Key Terms & Definitions

| Term                 | Definition                                                                      |
| -------------------- | ------------------------------------------------------------------------------- |
| **Provisioner**      | Terraform construct that executes scripts/commands during resource lifecycle    |
| **local-exec**       | Provisioner that runs commands on machine executing Terraform                   |
| **remote-exec**      | Provisioner that runs commands on remote resource via SSH/WinRM                 |
| **file Provisioner** | Provisioner that uploads files from local to remote machine                     |
| **Connection Block** | Configuration defining how Terraform connects to remote resources               |
| **Tainted Resource** | Resource marked for recreation due to provisioner failure                       |
| **self**             | Special variable referring to current resource in connection/provisioner blocks |
| **inline**           | Argument in remote-exec providing list of commands to execute                   |
| **on_failure**       | Argument controlling behavior when provisioner fails                            |
| **when**             | Argument specifying when provisioner runs (create or destroy)                   |

## Common Exam Traps

1. **Provisioner Execution Location**
   - `local-exec` runs on Terraform workstation
   - `remote-exec` runs on remote resource
   - `file` uploads from local to remote

2. **Provisioner Placement**
   - Must be inside resource block
   - Cannot stand alone
   - Multiple provisioners allowed per resource

3. **Connection Block Requirement**
   - Required for `remote-exec` and `file`
   - Not needed for `local-exec`
   - Must specify authentication method

4. **self Reference**
   - Use `self.public_ip` in connection block
   - Refers to current resource being created
   - Not `aws_instance.name.public_ip`

5. **Provisioner Execution Order**
   - Execute in order defined in configuration
   - All provisioners run after resource creation
   - Use `when = destroy` for cleanup

6. **Failure Behavior**
   - Default: Failure taints resource
   - Tainted resources recreated on next apply
   - Use `on_failure = continue` to ignore failures

7. **Security Group Timing**
   - Security groups must exist before provisioner runs
   - SSH must be allowed for remote-exec
   - Implicit dependencies usually sufficient

8. **Key Permissions**
   - SSH requires private key permissions 600
   - Use `local-exec` to set permissions
   - Or set `file_permission` on `local_file`

9. **Provisioners as Last Resort**
   - HashiCorp recommends alternatives
   - Use user_data, cloud-init, or config management
   - Provisioners reduce portability

10. **Connection Types**
    - SSH for Linux/Unix
    - WinRM for Windows
    - Must match target OS

## Updated Information (as of 2025-01-XX)

### Provisioner Recommendations

- **HashiCorp stance**: Provisioners remain "last resort"
- **Preferred alternatives**:
  - AWS: Use `user_data` or `user_data_base64`
  - Cloud-init for cross-platform initialization
  - Configuration management tools (Ansible, Chef, Puppet)
  - Container images with pre-installed software

### Security Best Practices

- **SSH access**: Never use `0.0.0.0/0` in production
- **Recommended**: Use AWS Systems Manager Session Manager (no SSH required)
- **Key management**: Use AWS Secrets Manager or Parameter Store
- **Bastion hosts**: Implement for production SSH access

### Modern Alternatives

**user_data Example:**

```hcl
resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"

  user_data = <<-EOF
              #!/bin/bash
              apt-get update
              apt-get install -y nginx
              systemctl start nginx
              EOF
}
```

**cloud-init Example:**

```hcl
resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"

  user_data = templatefile("${path.module}/cloud-init.yaml", {
    app_version = var.app_version
  })
}
```

### Connection Block Enhancements

- **Terraform 1.2+**: Improved error messages for connection failures
- **Timeout configuration**: Set connection timeout explicitly
  ```hcl
  connection {
    type        = "ssh"
    user        = "ubuntu"
    private_key = file("key.pem")
    host        = self.public_ip
    timeout     = "5m"
  }
  ```

### Instance Metadata Service v2 (IMDSv2)

- **AWS recommendation**: Enable IMDSv2 for enhanced security
  ```hcl
  metadata_options {
    http_endpoint               = "enabled"
    http_tokens                 = "required"  # IMDSv2
    http_put_response_hop_limit = 1
  }
  ```

### Terraform 1.x Compatibility

- All provisioner syntax remains unchanged
- `self` reference behavior consistent
- Connection block format unchanged
- No breaking changes in provisioner functionality
