# Terraform Resource Block

## Overview

Resource blocks are the fundamental building blocks of Terraform configurations, representing infrastructure objects such as virtual networks, compute instances, DNS records, and other cloud resources. Without resource blocks, Terraform cannot create or manage infrastructure. All other block types (provider, variable, output, etc.) serve as supporting components for resource blocks.

## Concepts

- **Resource Blocks**: Core Terraform construct for defining infrastructure components
- **Resource Types**: Provider-specific resource definitions (e.g., aws_instance, aws_s3_bucket)
- **Resource Naming**: Unique identifiers within Terraform configuration
- **Resource Arguments**: Configuration parameters specific to each resource type
- **Resource Dependencies**: Implicit and explicit relationships between resources

## Providers & Resources

### Resource Block Syntax

```hcl
resource "<RESOURCE_TYPE>" "<LOCAL_NAME>" {
  # Resource arguments
  <IDENTIFIER> = <EXPRESSION>
}
```

**Line-by-line Comments:**

```hcl
# Resource block declaration with type and local name
# Configuration arguments specific to resource type
```

### Resource Identification

**Resource ID Format**: `<resource_type>.<local_name>`

**Example**: `aws_route_table.public_route_table`

- **Resource Type**: `aws_route_table`
- **Local Name**: `public_route_table`
- **Uniqueness**: Must be unique per resource type within configuration

## Terraform Workflow

### Examining Existing Resources

```hcl
resource "aws_route_table" "public_route_table" {
  vpc_id = aws_vpc.vpc.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.internet_gateway.id
  }

  tags = {
    Name      = "demo_public_rtb"
    Terraform = "true"
  }
}
```

**Line-by-line Comments:**

```hcl
# Route table resource declaration
# Associate with VPC using interpolation
# Define routing rule for internet traffic
# Route all traffic (0.0.0.0/0) to internet gateway
# Reference internet gateway resource
# Apply metadata tags to resource
```

### Code Walkthrough

This resource block demonstrates key concepts:

- **Resource Type**: `aws_route_table` defines AWS route table resource
- **Local Name**: `public_route_table` provides unique identifier in configuration
- **Required Arguments**: `vpc_id` is mandatory for route tables
- **Nested Blocks**: `route` block defines routing rules
- **Interpolation**: References other resources using `aws_vpc.vpc.id` syntax
- **Tags**: Metadata for resource identification and management

### Creating S3 Bucket Resource

```hcl
resource "aws_s3_bucket" "my-new-S3-bucket" {
  bucket = "my-new-tf-test-bucket-unique-name"

  tags = {
    Name    = "My S3 Bucket"
    Purpose = "Intro to Resource Blocks Lab"
  }
}

resource "aws_s3_bucket_ownership_controls" "my_new_bucket_acl" {
  bucket = aws_s3_bucket.my-new-S3-bucket.id

  rule {
    object_ownership = "BucketOwnerPreferred"
  }
}
```

**Line-by-line Comments:**

```hcl
# S3 bucket resource declaration
# Globally unique bucket name required
# Resource metadata tags
# Separate ACL resource (newer AWS provider pattern)
# Reference parent bucket using interpolation
# Configure bucket ownership settings
```

**Important Considerations**:

- **Global Uniqueness**: S3 bucket names must be globally unique across all AWS accounts
- **Resource Separation**: ACL configuration separated from bucket resource in newer provider versions
- **No Cost**: S3 buckets incur no charges unless data is stored

### Creating Security Group Resource

```hcl
resource "aws_security_group" "my-new-security-group" {
  name        = "web_server_inbound"
  description = "Allow inbound traffic on tcp/443"
  vpc_id      = aws_vpc.vpc.id

  ingress {
    description = "Allow 443 from the Internet"
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name    = "web_server_inbound"
    Purpose = "Intro to Resource Blocks Lab"
  }
}
```

**Line-by-line Comments:**

```hcl
# Security group resource declaration
# Security group name in AWS
# Human-readable description
# Associate with VPC
# Ingress (inbound) rule definition
# Rule description for documentation
# Port range (443 for HTTPS)
# TCP protocol specification
# Allow from any IP address (0.0.0.0/0)
# Resource tags
```

## State Management

### Resource Lifecycle

1. **Plan Phase**: Terraform calculates required changes
2. **Apply Phase**: Resources created, updated, or destroyed
3. **State Update**: Resource metadata stored in state file
4. **Dependency Tracking**: Resource relationships maintained

### Resource Replacement

## Pitfalls & Best Practices

### Resource Configuration

- **Provider Documentation**: Always consult provider docs for required/optional arguments
- **Unique Naming**: Ensure resource names are unique within resource type
- **Global Constraints**: Be aware of platform-specific naming requirements (e.g., S3 global uniqueness)
- **Tag Consistently**: Use tags for resource identification and cost tracking

### Provider Management

- **Missing Providers**: Run `terraform init` when adding resources from new providers
- **Version Locking**: Pin provider versions for consistency
- **Provider Updates**: Test provider updates in non-production environments

### Resource Dependencies

- **Implicit Dependencies**: Terraform detects dependencies through interpolation
- **Explicit Dependencies**: Use `depends_on` when implicit detection insufficient
- **Circular Dependencies**: Avoid circular resource references

### Common Mistakes

- **Forgetting terraform init**: Adding new provider resources without initialization
- **Hardcoded Values**: Using static values instead of variables or data sources
- **Missing Required Arguments**: Omitting mandatory resource parameters
- **Incorrect Interpolation**: Syntax errors in resource references

## Key Terms & Definitions

- **Resource Block**: HCL block defining infrastructure component
- **Resource Type**: Provider-specific resource identifier (e.g., aws_instance)
- **Local Name**: User-defined identifier for resource within configuration
- **Resource ID**: Combination of resource type and local name
- **Resource Arguments**: Configuration parameters for resource
- **Interpolation**: Referencing values from other resources or variables
- **Resource Replacement**: Destroying and recreating resource due to immutable property changes
- **Nested Blocks**: Sub-blocks within resource for complex configuration

## Common Exam Traps

- **Resource Block Importance**: Understanding that resource blocks are essential for infrastructure creation
- **Resource Naming**: Knowing resource IDs must be unique per type
- **Provider Requirements**: Recognizing when new providers need initialization
- **Argument Types**: Distinguishing between required and optional arguments
- **Resource References**: Proper syntax for interpolating resource attributes
- **State Impact**: Understanding how resource changes affect state file
- **Replacement vs. Update**: Knowing which changes force resource replacement
