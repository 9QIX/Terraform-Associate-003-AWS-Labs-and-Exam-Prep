# HashiCorp Configuration Language (HCL)

## Overview

HashiCorp Configuration Language (HCL) is the declarative language used to write Terraform configurations. HCL is designed to be both human and machine readable, providing a structured syntax for defining infrastructure resources and their relationships.

## Concepts

- **Human and Machine Readable**: HCL balances readability for humans with parsability for machines
- **Declarative Syntax**: Describes desired infrastructure state rather than procedural steps
- **Block-Based Structure**: Configuration organized into logical blocks with specific purposes
- **Expression Language**: Supports variables, functions, and dynamic expressions

## HCL Syntax Structure

### Basic Block Syntax

```hcl
<BLOCK TYPE> "<BLOCK LABEL>" "<BLOCK LABEL>" {
  # Block body
  <IDENTIFIER> = <EXPRESSION>
}
```

**Line-by-line Comments:**

```hcl
# Block type defines the kind of configuration block
# Block labels provide additional context and naming
# Block body contains configuration arguments
# Identifiers are argument names with assigned values
```

### Resource Block Example

```hcl
resource "aws_instance" "web_server" {
  ami           = "ami-0c02fb55956c7d316"
  instance_type = var.instance_type

  tags = {
    Name = "Web Server"
  }
}
```

**Line-by-line Comments:**

```hcl
# Resource block type for infrastructure components
# AWS instance resource type and local identifier
# AMI ID for the EC2 instance image
# Instance size using variable reference
# Resource tags for identification and management
```

### Code Walkthrough

The resource block demonstrates key HCL concepts:

- **Block Type**: `resource` indicates infrastructure component definition
- **Resource Type**: `aws_instance` specifies the AWS EC2 instance resource
- **Local Name**: `web_server` provides unique identifier within configuration
- **Arguments**: `ami`, `instance_type`, and `tags` configure resource properties
- **Expressions**: `var.instance_type` references a variable for dynamic values

## Terraform Configuration Block Types

### Core Block Types

| Block Type  | Purpose                             | Example Usage                        |
| ----------- | ----------------------------------- | ------------------------------------ |
| `terraform` | Terraform settings and requirements | Provider version constraints         |
| `provider`  | Provider configuration              | AWS region, credentials              |
| `resource`  | Infrastructure components           | EC2 instances, VPCs, databases       |
| `data`      | Data source lookups                 | AMI IDs, availability zones          |
| `variable`  | Input variables                     | Parameterized configurations         |
| `locals`    | Local variables                     | Computed values and expressions      |
| `output`    | Output values                       | Resource attributes for external use |
| `module`    | Module calls                        | Reusable configuration components    |

### Provider Block Configuration

```hcl
provider "aws" {
  region = "us-east-1"
  # Credentials can be specified but not recommended
  # access_key = "AKIAIOSFODNN7EXAMPLE"
  # secret_key = "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
}
```

**Line-by-line Comments:**

```hcl
# AWS provider configuration block
# Specify target AWS region for resources
# Hardcoded credentials not recommended for security
# Use environment variables or IAM roles instead
```

### Data Source Example

```hcl
data "aws_ami" "ubuntu" {
  most_recent = true

  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd/ubuntu-focal-20.04-amd64-server-*"]
  }

  owners = ["099720109477"] # Canonical
}
```

**Line-by-line Comments:**

```hcl
# Data source for AMI lookup
# Get the most recent matching AMI
# Filter by AMI name pattern
# Ubuntu 20.04 LTS server images
# Canonical's AWS account ID for official Ubuntu images
```

## Terraform Workflow

### Configuration Development Process

1. **Write Configuration**: Create `.tf` files with HCL syntax
2. **Format Code**: Use `terraform fmt` for consistent formatting
3. **Validate Syntax**: Run `terraform validate` to check configuration
4. **Initialize Directory**: Execute `terraform init` to download providers
5. **Plan Changes**: Use `terraform plan` to preview infrastructure changes
6. **Apply Configuration**: Run `terraform apply` to create resources

### CLI Help and Documentation

```bash
# Get general help
terraform -help

# Get help for specific commands
terraform plan -help
```

## Providers & Resources

### Provider Credential Management

**Environment Variables (Recommended)**:

```bash
export AWS_ACCESS_KEY_ID="your-access-key"
export AWS_SECRET_ACCESS_KEY="your-secret-key"
```

**Provider Block (Not Recommended)**:

```hcl
provider "aws" {
  access_key = "AKIAIOSFODNN7EXAMPLE"
  secret_key = "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
  region     = "us-east-1"
}
```

### Resource Identification Requirements

- **Unique Names**: Each resource type must have unique local names
- **Resource Addressing**: Format: `resource_type.local_name`
- **Cross-References**: Resources can reference each other using addressing

## Pitfalls & Best Practices

### Security Considerations

- **Never Hardcode Credentials**: Use environment variables or IAM roles
- **Version Control Safety**: Avoid committing sensitive data to repositories
- **Provider Authentication**: Prefer IAM roles over access keys when possible

### Configuration Management

- **Consistent Formatting**: Use `terraform fmt` regularly
- **Validation Checks**: Run `terraform validate` before planning
- **Modular Design**: Organize configuration into logical files and modules
- **Variable Usage**: Parameterize configurations for reusability

### Common Syntax Errors

- **Missing Quotes**: String values must be quoted
- **Incorrect Indentation**: Use consistent spacing for readability
- **Invalid References**: Ensure variable and resource references exist
- **Block Structure**: Maintain proper opening and closing braces

## Key Terms & Definitions

- **HCL (HashiCorp Configuration Language)**: Declarative language for Terraform configurations
- **Block**: Fundamental configuration unit with type, labels, and body
- **Block Type**: Category of configuration block (resource, provider, variable, etc.)
- **Block Label**: Additional identifiers providing context to blocks
- **Argument**: Key-value pair within block body defining configuration
- **Expression**: Dynamic value that can include variables, functions, and references
- **Resource Type**: Specific infrastructure component type (aws_instance, aws_vpc)
- **Local Name**: User-defined identifier for resources within configuration
