# Terraform State — Refresh and Drift Detection

## Overview

Terraform must keep its state file synchronized with real-world infrastructure. The **refresh** operation reads current settings from all managed remote objects and updates the state file to match. This is critical for detecting **drift** — changes made to infrastructure outside of the Terraform workflow (e.g., manual console edits, scripts, incident response).

Refreshing state is the first step of every `terraform plan`. If you need to perform *only* the refresh step without generating a full plan, use `terraform plan -refresh-only` or `terraform apply -refresh-only`.

> **Important**: The standalone `terraform refresh` command is deprecated. Use `-refresh-only` mode instead.

---

## Concepts

- **State Refresh** — Reading current attributes of all managed remote objects and updating the state file to match reality.
- **Drift** — Any change to infrastructure that occurs outside of the Terraform workflow (manual edits, other tools, API calls).
- **Refresh-Only Mode** — A safer alternative to `terraform refresh` that shows detected changes and requires confirmation before updating state.
- **Drift Remediation** — Running `terraform apply` after detecting drift reverts infrastructure to match the configuration (unless the configuration is updated to reflect the drift).

---

## Terraform Workflow

### Drift Detection and Resolution Cycle

1. Infrastructure is deployed via `terraform apply`.
2. Out-of-band changes occur (manual edits, scripts, etc.).
3. Drift is detected via refresh (`terraform plan -refresh-only`).
4. Decision point:
   - **Revert drift** → Run `terraform apply` (configuration wins).
   - **Accept drift** → Run `terraform apply -refresh-only` to update state, then update configuration to match.

### Inspecting State Before and After Refresh

```bash
terraform state list
```

```text
# Line-by-line Comments
terraform state list    # Lists all resource addresses tracked in state
```

```bash
terraform state show aws_instance.web_server
```

```text
# Line-by-line Comments
terraform state show aws_instance.web_server    # Displays all attributes of a specific resource in state
```

#### Code Walkthrough

- `terraform state list` provides a high-level inventory of all tracked resources (data sources, resources, modules).
- `terraform state show <address>` displays the full attribute set for a single resource, including computed values like `id`, `arn`, `public_ip`, and `tags`.
- Comparing output before and after a refresh reveals which attributes have drifted.

### Detecting Drift with Refresh-Only Mode (Recommended)

```bash
terraform plan -refresh-only
```

```text
# Line-by-line Comments
terraform plan -refresh-only    # Refreshes state and shows detected drift without proposing infrastructure changes
```

Sample output:

```text
Note: Objects have changed outside of Terraform

Terraform detected the following changes made outside of Terraform since the last "terraform apply":

  # aws_instance.web_server has changed
  ~ resource "aws_instance" "web_server" {
        id   = "i-0fdab85c96f92f0e9"
      ~ tags = {
          ~ "Name" = "Web EC2 Server" -> "Web EC2 Server - My App"
        }
    }

This is a refresh-only plan, so Terraform will not take any actions to undo these.
```

#### Code Walkthrough

- `-refresh-only` performs only the refresh step of `terraform plan`.
- It reports what changed in real infrastructure versus what Terraform's state currently records.
- No infrastructure modifications are proposed — only state updates.
- This provides a safe review step before committing changes to state.

---

### Applying Refresh-Only to Update State (Accept Drift)

```bash
terraform apply -refresh-only
```

```text
# Line-by-line Comments
terraform apply -refresh-only    # Updates state to match real infrastructure; does not modify remote objects
```

When prompted:

```text
Would you like to update the Terraform state to reflect these detected changes?
  Terraform will write these changes to the state without modifying any real infrastructure.
  There is no undo. Only 'yes' will be accepted to confirm.

  Enter a value: yes
```

#### Code Walkthrough

- Updates the state file to reflect the current real-world configuration.
- Does **not** modify any remote objects.
- After this, `terraform state show` reflects the drifted values.
- If the configuration is not updated to match, the next `terraform apply` will revert the drift.

---

### Reverting Drift (Configuration Wins)

```bash
terraform apply
```

```text
# Line-by-line Comments
terraform apply    # Compares configuration to state, proposes changes to align infrastructure with config
```

Sample output:

```text
  # aws_instance.web_server will be updated in-place
  ~ resource "aws_instance" "web_server" {
        id   = "i-0fdab85c96f92f0e9"
      ~ tags = {
          ~ "Name" = "Web EC2 Server - My App" -> "Web EC2 Server"
        }
    }

Plan: 0 to add, 1 to change, 0 to destroy.
```

#### Code Walkthrough

- Terraform detects that the state (updated via refresh) no longer matches the configuration.
- It proposes reverting the tag back to the value defined in the `.tf` files.
- Confirming with `yes` updates the remote object to match the configuration, eliminating drift.

## Comparison: `terraform refresh` vs. `-refresh-only`

| Aspect | `terraform refresh` (Deprecated) | `terraform plan -refresh-only` | `terraform apply -refresh-only` |
|--------|----------------------------------|-------------------------------|--------------------------------|
| Updates state | Yes (immediately) | No (preview only) | Yes (after confirmation) |
| Modifies infrastructure | No | No | No |
| Shows changes before applying | No | Yes | Yes |
| Requires confirmation | No | N/A (plan only) | Yes |
| Risk level | High (silent state update) | Low (read-only) | Medium (explicit confirmation) |
| Recommended | **No** | **Yes** (detection) | **Yes** (state update) |

## Drift Resolution Decision Matrix

| Scenario | Action | Command |
|----------|--------|---------|
| Detect drift without changing anything | Preview | `terraform plan -refresh-only` |
| Accept drift into state (intentional change) | Update state only | `terraform apply -refresh-only`, then update `.tf` config |
| Revert drift to match configuration | Revert infrastructure | `terraform apply` |
| Ignore drift temporarily | Do nothing | No command needed (drift persists) |

## Pitfalls & Best Practices

- **Do not use `terraform refresh` directly** — It updates state without confirmation, risking accidental state corruption if credentials are misconfigured (provider may report all objects as deleted).
- **Always use `-refresh-only` for drift detection** — Provides a review step before state modification.
- **Update configuration after accepting drift** — If you run `terraform apply -refresh-only` to accept out-of-band changes, update the `.tf` files to match; otherwise the next `apply` reverts the changes.
- **Refresh is automatic in `plan` and `apply`** — You rarely need to refresh manually; every `plan`/`apply` reads current remote state first.
- **Drift can affect any attribute** — Not just tags; instance types, security groups, IAM policies, and any mutable attribute can drift.
- **Misconfigured credentials during refresh are dangerous** — If a provider cannot authenticate, it may interpret all resources as deleted, leading to state corruption.

## Common Exam Traps

| Trap | Correct Understanding |
|------|----------------------|
| "`terraform refresh` modifies infrastructure" | **False** — It only modifies the state file, never remote objects. |
| "`terraform refresh` is the recommended way to detect drift" | **False** — `terraform refresh` is deprecated. Use `terraform plan -refresh-only`. |
| "Drift is automatically corrected by Terraform" | **False** — Drift is only corrected when `terraform apply` is run and the change is confirmed. |
| "`terraform plan` does not perform a refresh" | **False** — Refresh is the *first step* of every `terraform plan` by default. |
| "`terraform apply -refresh-only` changes infrastructure" | **False** — It only updates the state file to match reality; no infrastructure changes occur. |
| "You must run `terraform refresh` before `terraform plan`" | **False** — `plan` performs refresh automatically. Manual refresh is unnecessary. |
| "Accepting drift with `-refresh-only` is permanent" | **Partially true** — State is updated, but the next `apply` will revert infrastructure if config is not also updated. |
| "The `-refresh-only` flag can be used with `terraform destroy`" | **False** — `-refresh-only` is only valid with `plan` and `apply`. |

## Key Terms & Definitions

| Term | Definition |
|------|-----------|
| **Drift** | Any difference between the desired state (configuration) and the actual state of infrastructure, caused by out-of-band changes. |
| **State Refresh** | The process of querying real infrastructure and updating the state file to reflect current attributes. |
| **`terraform refresh`** | Deprecated command that performs an unconditional state refresh without confirmation. |
| **`-refresh-only`** | Flag for `plan`/`apply` that limits the operation to refreshing state only, with a review/confirmation step. |
| **Out-of-Band Change** | Any modification made to infrastructure outside of Terraform (console, CLI, scripts, other tools). |
| **Drift Remediation** | The process of resolving differences between configuration and reality, either by reverting changes or updating configuration. |
| **`terraform state show`** | Command that displays all attributes of a single resource as recorded in the state file. |
| **`terraform state list`** | Command that lists all resource addresses currently tracked in state. |

## Updated Information (as of 2025-07-14)

| Change | Details |
|--------|---------|
| **`terraform refresh` deprecated** | The standalone `terraform refresh` command is deprecated as of Terraform v1.5+ due to the risk of silent state corruption. Use `terraform plan -refresh-only` to preview drift and `terraform apply -refresh-only` to commit state updates with confirmation. |
| **Default refresh behavior** | As of Terraform v1.x, both `plan` and `apply` perform a refresh by default. Use `-refresh=false` to skip the refresh step if needed (e.g., for performance in large state files). |
| **IMDSv2 metadata** | The lab's EC2 instance shows `http_tokens = "optional"` (IMDSv1 allowed). AWS now recommends `http_tokens = "required"` to enforce IMDSv2 for improved security. |
