# Terraform State — Sensitive Data

## Overview

Terraform state files store all resource attributes and output values in JSON format. This includes **sensitive data** such as database passwords, API keys, and any secrets returned by providers. By default, local state is stored as **plaintext JSON** with no encryption beyond the filesystem. Marking values as `sensitive` in configuration only redacts them from CLI output and logs — **it does not encrypt or remove them from the state file**.

Protecting the state file itself is therefore critical to maintaining security.

---

## Concepts

- **Sensitive Attribute** — The `sensitive = true` argument on variables and outputs that suppresses values from CLI output, logs, and plan displays.
- **State File Plaintext** — Regardless of the `sensitive` flag, all values (including sensitive ones) are stored in cleartext within the state file.
- **`nonsensitive()` Function** — Explicitly marks a sensitive value as non-sensitive for output purposes, bypassing the redaction.
- **Defense in Depth** — Multiple layers of protection (encryption, access control, sensitive flags) are needed since no single mechanism fully protects secrets.

## State Management

### Local State — Plaintext JSON

```json
{
  "version": 4,
  "terraform_version": "1.1.1",
  "serial": 28,
  "lineage": "3f020a98-09d2-d827-e51d-673c7ec480bf",
  "outputs": {
    "public_ip": {
      "value": "34.224.58.141",
      "type": "string"
    }
  },
  "resources": [...]
}
```

```text
# Line-by-line Comments
"version": 4                    # State file format version
"terraform_version": "1.1.1"    # Terraform CLI version that wrote this state
"serial": 28                    # Incremented on every state change
"lineage": "..."                # Unique ID tying state to a specific init
"outputs": { ... }              # All output values stored in plaintext
"resources": [...]              # Full resource attributes including secrets
```

#### Code Walkthrough

- The state file contains **every attribute** of every managed resource — including computed secrets (e.g., RDS passwords, TLS private keys).
- `outputs` section stores values in cleartext even when marked `sensitive = true` in configuration.
- The `sensitive` metadata flag appears in the JSON but does **not** encrypt the value.

### Marking Variables and Outputs as Sensitive

```hcl
variable "first_name" {
  type      = string
  sensitive = true
  default   = "<name>"
}

variable "phone_number" {
  type      = string
  sensitive = true
  default   = "<phone number>"
}

locals {
  contact_info = {
    first_name   = var.first_name
    phone_number = var.phone_number
  }

  my_number = nonsensitive(var.phone_number)
}

output "first_name" {
  sensitive = true
  value     = local.contact_info.first_name
}

output "phone_number" {
  sensitive = true
  value     = local.contact_info.phone_number
}

output "my_number" {
  value = local.my_number
}
```

```text
# Line-by-line Comments
variable "first_name" {
  type      = string           # Variable type constraint
  sensitive = true             # Redacts value from CLI output and logs
  default   = "<name>"        # Default value (still stored plaintext in state)
}

variable "phone_number" {
  type      = string
  sensitive = true
  default   = "<phone number>"
}

locals {
  contact_info = {
    first_name   = var.first_name      # Inherits sensitive flag from variable
    phone_number = var.phone_number    # Inherits sensitive flag from variable
  }

  my_number = nonsensitive(var.phone_number)  # Strips sensitive flag; value displayed openly
}

output "first_name" {
  sensitive = true                            # Required when output derives from sensitive values
  value     = local.contact_info.first_name
}

output "phone_number" {
  sensitive = true                            # Required — Terraform errors without this
  value     = local.contact_info.phone_number
}

output "my_number" {
  value = local.my_number                     # Not sensitive — displayed in CLI
}
```

#### Code Walkthrough

- Variables with `sensitive = true` propagate sensitivity to any expression that references them.
- Outputs that derive from sensitive values **must** also declare `sensitive = true` — otherwise Terraform raises an error to prevent accidental exposure.
- The `nonsensitive()` function explicitly strips the sensitive flag. Use only when the value is truly safe to expose (e.g., non-secret metadata).
- After `terraform apply`, sensitive outputs display as `<sensitive>` in the terminal; non-sensitive outputs show plaintext.

---

### Sensitive Output Error

If an output references a sensitive value without `sensitive = true`:

```text
Error: Output refers to sensitive values

To reduce the risk of accidentally exporting sensitive data that was intended
to be only internal, Terraform requires that any root module output containing
sensitive data be explicitly marked as sensitive, to confirm your intent.
```

**Fix**: Add `sensitive = true` to the output block.

### State File with Sensitive Values

```json
{
  "outputs": {
    "first_name": {
      "value": "Terraform",
      "type": "string",
      "sensitive": true
    },
    "phone_number": {
      "value": "867-5309",
      "type": "string",
      "sensitive": true
    },
    "my_number": {
      "value": "867-5309",
      "type": "string"
    }
  }
}
```

> **Critical**: The `"sensitive": true` metadata flag in the state file is informational only. The actual **value is stored in plaintext**. Anyone with access to the state file can read all sensitive values.

## Pitfalls & Best Practices

### State Protection Strategy

| Layer                 | Action                                                          | Effect                                |
| --------------------- | --------------------------------------------------------------- | ------------------------------------- |
| 1. Code               | Mark variables/outputs as `sensitive = true`                    | Redacts from CLI, logs, plan output   |
| 2. Backend encryption | Use encrypted backends (S3+SSE, GCS, Azure Blob, HCP Terraform) | Encrypts state at rest and in transit |
| 3. Access control     | Restrict backend access via IAM, RBAC, or workspace permissions | Limits who can read state             |
| 4. TLS                | Connect to backend only via HTTPS/TLS                           | Encrypts state in transit             |
| 5. Audit              | Enable logging on backend (S3 access logs, CloudTrail)          | Detects unauthorized access           |

### Best Practices

- **Treat state as sensitive** — Assume plaintext by default; protect accordingly.
- **Encrypt the backend** — Use backends that support encryption at rest (AES-256) and in transit (TLS).
- **Control access strictly** — Use IAM policies, HCP Terraform team permissions, or equivalent to restrict state access to a minimal set of trusted operators.
- **Never commit state to version control** — Add `*.tfstate` and `*.tfstate.backup` to `.gitignore`.
- **Use `sensitive = true` on all secrets** — Prevents accidental exposure in logs, CI output, and terminal.
- **Avoid `nonsensitive()` unless intentional** — Only use when you deliberately want to expose a value.
- **Use remote backends for team environments** — Local state offers no access control or encryption.
- **Rotate secrets exposed in state** — If state is compromised, rotate all credentials stored within it.

## Comparison: Sensitive Data Protection by Backend

| Backend       | Encryption at Rest               | Encryption in Transit | Access Control             | State Versioning  |
| ------------- | -------------------------------- | --------------------- | -------------------------- | ----------------- |
| Local         | None (plaintext file)            | N/A                   | OS file permissions only   | None              |
| S3            | SSE-S3 or SSE-KMS (AES-256)      | TLS (automatic)       | IAM policies               | S3 versioning     |
| GCS           | AES-256 (default)                | TLS (automatic)       | IAM                        | Object versioning |
| Azure Blob    | AES-256 (default)                | TLS (automatic)       | Azure RBAC                 | Blob versioning   |
| HCP Terraform | AES-256 (unique key per version) | TLS (automatic)       | Team/workspace permissions | Built-in          |

## Common Exam Traps

| Trap                                                                | Correct Understanding                                                                                                                                                                                          |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "`sensitive = true` encrypts the value in state"                    | **False** — It only redacts from CLI/logs. Values remain plaintext in state.                                                                                                                                   |
| "Marking a variable as sensitive protects it everywhere"            | **False** — State file still contains the plaintext value. Backend encryption and access control are separate concerns.                                                                                        |
| "Outputs can reference sensitive values without marking"            | **False** — Terraform errors if a root module output references sensitive data without `sensitive = true`.                                                                                                     |
| "`nonsensitive()` removes the value from state"                     | **False** — It only strips the sensitive metadata flag. The value is still stored in state.                                                                                                                    |
| "Local state is encrypted by default"                               | **False** — Local state is plaintext JSON with no encryption.                                                                                                                                                  |
| "Using a remote backend eliminates the need for `sensitive = true`" | **False** — Both are needed. `sensitive` prevents log exposure; backend encryption protects at rest.                                                                                                           |
| "Child module outputs inherit sensitivity automatically"            | **True for expressions** — If a child module output references a sensitive input, the sensitivity propagates. But the child module output block itself may still need `sensitive = true` depending on context. |

## Key Terms & Definitions

| Term                      | Definition                                                                                                                                |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **`sensitive = true`**    | HCL argument that prevents a variable or output value from being displayed in CLI output, logs, and plan diffs.                           |
| **`nonsensitive()`**      | Built-in function that explicitly removes the sensitive flag from a value, allowing it to be displayed or used in non-sensitive contexts. |
| **State File**            | JSON file (`terraform.tfstate`) containing the full attribute set of all managed resources, including secrets, in plaintext.              |
| **Encryption at Rest**    | Protecting stored data (e.g., state on disk) using cryptographic encryption (AES-256).                                                    |
| **Encryption in Transit** | Protecting data during transfer between client and backend using TLS/SSL.                                                                 |
| **IAM Policy**            | AWS Identity and Access Management rule controlling who can access specific resources (e.g., an S3 state bucket).                         |
| **Plaintext**             | Unencrypted, human-readable format — the default storage format for local Terraform state.                                                |

## Updated Information (as of 2025-07-14)

| Change                                       | Details                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`sensitive` on variables — plan behavior** | As of Terraform v1.0+, sensitivity propagates through expressions automatically. If a variable is sensitive, any local, output, or resource argument referencing it is treated as sensitive without needing additional annotations (except on root module outputs, which still require explicit `sensitive = true`). |
| **Ephemeral values (Terraform v1.10+)**      | Terraform introduced `ephemeral` resource and variable support to handle secrets that should never be persisted to state. For credentials that must not appear in state at all, consider using ephemeral inputs where supported by providers.                                                                        |
| **HCP Terraform encryption**                 | HCP Terraform now uses unique per-version encryption keys with additional controls via workspace-level permissions and run-level access tokens. The underlying encryption remains AES-256.                                                                                                                           |
| **`.gitignore` best practice**               | The official Terraform `.gitignore` template now includes `*.tfstate`, `*.tfstate.*`, and `crash.log` by default. Always verify these entries exist in your repository.                                                                                                                                              |
