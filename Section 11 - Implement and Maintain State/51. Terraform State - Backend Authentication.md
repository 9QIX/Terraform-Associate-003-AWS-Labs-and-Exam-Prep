# Terraform State - Backend Authentication

## Overview

Remote backends store Terraform state in centralized services, enabling team collaboration. However, state files contain sensitive information (database credentials, connection strings, resource metadata), requiring strict access control through authentication. This lab demonstrates authentication methods for two backend types: **AWS S3 (standard backend)** and **Terraform Cloud (remote enhanced backend)**.

---

## Concepts

### Why Backend Authentication Matters
- **Sensitive data exposure**: State files contain resource IDs, connection strings, credentials
- **Access control**: Limit who can read/modify state
- **Team collaboration**: Multiple users need authenticated access to shared state
- **Security best practice**: Never store credentials in code or version control

### Authentication Methods by Backend
| Backend Type | Authentication Method |
|--------------|----------------------|
| **AWS S3** | Environment variables, shared credentials file, IAM roles |
| **Terraform Cloud/Enterprise** | API tokens via `terraform login` |
| **Azure Storage** | Service principals, managed identities |
| **Google Cloud Storage** | Service accounts, application default credentials |

### Best Practices
- **Never hardcode credentials** in backend configuration
- **Use environment variables** or credential files
- **Leverage IAM policies** to restrict bucket/resource access
- **Enable encryption** for state at rest
- **Block public access** to state storage

## State Management

### Task 1: Authentication - S3 Standard Backend

#### Step 1.1: Create S3 Bucket

**AWS Console Steps:**
1. Navigate to S3 service
2. Click "Create bucket"
3. Bucket name: `my-terraform-state-<initials>` (must be globally unique)
4. **Block all public access**: ✅ Enabled (critical for security)
5. Leave other defaults
6. Click "Create bucket"

**Security Considerations:**
- Use IAM policies to restrict access to specific users/roles
- Enable versioning for state history
- Enable encryption at rest
- Configure bucket policies for least-privilege access

---

#### Step 1.2: Destroy Existing Infrastructure

```bash
terraform destroy
```

**Line-by-line Comments:**
```bash
# Removes all resources managed by current state
# Cleans up before migrating to new backend
# Responds 'yes' to confirmation prompt
```

**Code Walkthrough:**
- Clears existing local state before backend migration
- Alternative: Migrate state between backends (covered in future labs)
- Ensures clean starting point for S3 backend configuration

---

#### Step 1.3: Configure S3 Backend

```hcl
terraform {
  backend "s3" {
    bucket = "my-terraform-state-ghm"
    key    = "prod/aws_infra"
    region = "us-east-1"
  }
}
```

**Line-by-line Comments:**
```hcl
# Terraform configuration block
# Declares S3 as state backend
# S3 bucket name (must match created bucket)
# State file path within bucket (supports nested paths)
# AWS region where bucket resides
```

**Code Walkthrough:**
- Replaces `backend "local"` configuration
- `bucket`: Must match bucket created in Step 1.1
- `key`: Object path for state file (e.g., `prod/aws_infra` creates nested structure)
- `region`: Must match bucket's AWS region
- **Note**: Only one backend allowed per configuration
- Requires `terraform init -reconfigure` after changes

---

#### Step 1.4: Provide AWS Credentials (Environment Variables)

```bash
export AWS_ACCESS_KEY_ID="YOUR_AWS_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="YOUR_AWS_SECRET_ACCESS_KEY"
```

**Line-by-line Comments:**
```bash
# Sets AWS access key as environment variable
# Sets AWS secret key as environment variable
# Terraform automatically reads these variables
```

**Code Walkthrough:**
- Environment variables provide credentials without hardcoding
- Terraform AWS provider automatically detects these variables
- Variables persist for current terminal session only
- **Security**: Never commit credentials to version control

**Optional: Multi-Factor Authentication**
```bash
export AWS_SESSION_TOKEN="YOUR_SESSION_TOKEN"
```

**Optional: Shared Credentials File**
```hcl
terraform {
  backend "s3" {
    bucket                  = "my-terraform-state-ghm"
    key                     = "prod/aws_infra"
    region                  = "us-east-1"
    shared_credentials_file = "~/.aws/credentials"
  }
}
```

**Line-by-line Comments:**
```hcl
# S3 backend configuration
# Bucket, key, and region as before
# Path to AWS credentials file (default: ~/.aws/credentials)
```

---

#### Step 1.5: Verify Authentication

```bash
terraform init -reconfigure
```

**Line-by-line Comments:**
```bash
# Re-initializes working directory with new backend
# -reconfigure flag forces backend reconfiguration
# Validates authentication to S3 bucket
```

**Expected Output:**
```bash
Initializing the backend...

Successfully configured the backend "s3"! Terraform will automatically

```

**Code Walkthrough:**
- `-reconfigure` required when changing backend type
- Terraform validates credentials during initialization
- Creates backend connection without migrating existing state
- Failure indicates authentication or permission issues

#### Step 2.3: Authenticate via CLI

```bash
terraform login
```

**Line-by-line Comments:**
```bash
# Initiates authentication to Terraform Cloud
# Opens browser for token generation
# Stores token in credentials file
```

**Interactive Prompt:**
```bash
Terraform will request an API token for app.terraform.io using your browser.

If login is successful, Terraform will store the token in plain text in
the following file for use by subsequent commands:
    /Users/gabe/.terraform.d/credentials.tfrc.json

Do you want to proceed?
  Only 'yes' will be accepted to confirm.

  Enter a value: yes
```

**Code Walkthrough:**
1. User responds `yes` to proceed
2. Terraform opens browser to `https://app.terraform.io/app/settings/tokens?source=terraform-login`
3. User generates API token in Terraform Cloud UI
4. User copies token and pastes into CLI prompt
5. Terraform stores token in `~/.terraform.d/credentials.tfrc.json`

---

#### Generate API Token (Browser)

**Terraform Cloud UI Steps:**
1. Browser opens to token creation page
2. Enter token description (e.g., "CLI Access")
3. Click "Create API token"
4. Copy token to clipboard
5. Click "Done"

**Security Warning:**
- Token grants full access to Terraform Cloud account
- Never share or commit token to version control
- Treat as sensitive credential

---

#### Paste Token into CLI

```bash

  Enter a value: <paste-token-here>

The new API token will be used for any future Terraform command that must make
authenticated requests to app.terraform.io.
```

**Code Walkthrough:**
- Token input is hidden (no visual feedback)
- Terraform validates token with Terraform Cloud API
- Success message confirms authentication
- Token stored in `credentials.tfrc.json` for future use

#### Credentials File Location

**File Path:**
```

```

**File Format:**
```json

  "credentials": {
    "app.terraform.io": {

    }
  }

```

**Line-by-line Comments:**
```json

// Terraform Cloud hostname

```

## Terraform Workflow

### S3 Backend Workflow Summary

1. **Create S3 bucket** with public access blocked
2. **Destroy existing infrastructure** (or migrate state)
3. **Configure S3 backend** in `terraform.tf`
4. **Set AWS credentials** via environment variables
5. **Initialize backend** with `terraform init -reconfigure`
6. **Apply configuration** to write state to S3
7. **Verify state access** with `terraform state list`

---

### Remote Backend Workflow Summary

1. **Create Terraform Cloud account**
2. **Create organization** in Terraform Cloud
3. **Run `terraform login`** to authenticate
4. **Generate API token** in browser
5. **Paste token** into CLI prompt
6. **Verify authentication** success message
7. **Use remote backend** in future configurations

## Pitfalls & Best Practices

### Common Mistakes

| Mistake | Consequence | Solution |
|---------|-------------|----------|
| Hardcoding credentials in backend config | Credentials exposed in version control | Use environment variables or credential files |
| Public S3 bucket access | State file publicly accessible | Block all public access in bucket settings |
| Sharing API tokens | Unauthorized access to Terraform Cloud | Generate unique tokens per user/system |
| Forgetting `-reconfigure` flag | Backend not updated after config change | Always use `-reconfigure` when changing backends |
| Not setting IAM policies | Overly permissive state access | Implement least-privilege IAM policies |
| Committing credentials file | Token exposure in Git history | Add `credentials.tfrc.json` to `.gitignore` |

---

### Best Practices

#### S3 Backend
- **Use IAM roles** for EC2/Lambda instead of access keys
- **Enable S3 versioning** for state history
- **Enable encryption** at rest (SSE-S3 or SSE-KMS)
- **Implement bucket policies** for least-privilege access
- **Use DynamoDB** for state locking (covered in future labs)
- **Separate buckets** per environment (dev/staging/prod)

#### Terraform Cloud Backend
- **Enable two-factor authentication** on accounts
- **Use team tokens** for CI/CD pipelines
- **Rotate API tokens** regularly
- **Limit token scope** to specific organizations
- **Audit token usage** via Terraform Cloud UI
- **Revoke unused tokens** immediately

#### General
- **Never commit credentials** to version control
- **Use `.gitignore`** for credential files:
  ```
  .terraform.d/credentials.tfrc.json
  terraform.tfvars
  *.auto.tfvars
  ```
- **Rotate credentials** regularly
- **Monitor access logs** for unauthorized attempts
- **Document authentication methods** for team members

## Key Terms & Definitions

| Term | Definition |
|------|------------|
| **Backend Authentication** | Process of verifying identity before accessing remote state storage |
| **Standard Backend** | Backend that only stores state (e.g., S3, GCS, Azure Storage) |
| **Enhanced Backend** | Backend that stores state and executes operations (e.g., Terraform Cloud) |
| **API Token** | Credential for authenticating to Terraform Cloud/Enterprise |
| **Shared Credentials File** | File storing AWS credentials (default: `~/.aws/credentials`) |
| **Environment Variables** | Shell variables providing credentials to Terraform |
| **IAM Policy** | AWS policy defining permissions for users/roles |
| **State Encryption** | Encrypting state file at rest in storage backend |

## Common Exam Traps

- **Trap:** Believing credentials should be in backend configuration  
  **Reality:** Credentials should use environment variables or credential files

- **Trap:** Assuming all backends support authentication  
  **Reality:** Local backend has no authentication; remote backends require it

- **Trap:** Thinking S3 backend automatically encrypts state  
  **Reality:** Must explicitly enable encryption in bucket settings

- **Trap:** Believing `terraform login` is only for Terraform Cloud  
  **Reality:** Also works for Terraform Enterprise with custom hostname

- **Trap:** Assuming API tokens never expire  
  **Reality:** Tokens can be revoked; should be rotated regularly

- **Trap:** Thinking `-reconfigure` migrates state  
  **Reality:** `-reconfigure` only updates backend config; use `-migrate-state` for migration

- **Trap:** Believing IAM roles can't be used with S3 backend  
  **Reality:** EC2 instances can use IAM roles instead of access keys
