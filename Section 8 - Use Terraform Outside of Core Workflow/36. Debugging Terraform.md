# Debugging Terraform

## Overview

Terraform provides detailed logging capabilities through environment variables to help debug configuration issues, provider interactions, and workflow problems. Logging can be enabled at various verbosity levels and directed to console output or persistent log files for analysis and troubleshooting.

## Concepts

### Logging Fundamentals

- **Environment Variables**: Control logging through `TF_LOG` and `TF_LOG_PATH`
- **Log Levels**: Five verbosity levels from ERROR (least) to TRACE (most verbose)
- **Output Destinations**: Console (stderr) or persistent log files
- **Debug Information**: API calls, provider interactions, and internal workflows

### Key Benefits

- Detailed visibility into Terraform's internal operations
- API call inspection and response analysis
- Provider workflow debugging
- Configuration parsing and validation insights

## Terraform Workflow

### Enable Console Logging

**Linux/macOS:**

```bash
export TF_LOG=TRACE
terraform apply
```

**PowerShell:**

```powershell
$env:TF_LOG="TRACE"
terraform apply
```

**Line-by-line Comments:**

```bash
# Set logging to most verbose level
# Execute command with debug output to stderr
```

**Code Walkthrough:**
Setting `TF_LOG` enables detailed logging to stderr. The TRACE level provides maximum verbosity, showing all internal operations, API calls, and provider interactions. Other levels (DEBUG, INFO, WARN, ERROR) provide progressively less detail.

### Enable File Logging

**Linux/macOS:**

```bash
export TF_LOG=TRACE
export TF_LOG_PATH="terraform_log.txt"
terraform init -upgrade
```

**PowerShell:**

```powershell
$env:TF_LOG="TRACE"
$env:TF_LOG_PATH="terraform_log.txt"
terraform init -upgrade
```

**Line-by-line Comments:**

```bash
# Enable trace-level logging
# Direct output to specific log file
# Run command with logging to file
```

**Code Walkthrough:**
`TF_LOG_PATH` redirects debug output from stderr to a specified file. Both `TF_LOG` and `TF_LOG_PATH` must be set for file logging to work. This approach is useful for sharing debug information or analyzing complex issues offline.

### Disable Logging

**Linux/macOS:**

```bash
export TF_LOG=""
export TF_LOG_PATH=""
```

**PowerShell:**

```powershell
$env:TF_LOG=""
$env:TF_LOG_PATH=""
```

**Line-by-line Comments:**

```bash
# Clear logging level variable
# Clear log file path variable
```

**Code Walkthrough:**
Setting environment variables to empty strings disables logging. This removes the performance overhead and verbose output once debugging is complete.

## State Management

### Debug Information Categories

- **Configuration Parsing**: How Terraform reads and validates HCL files
- **State Comparison**: Differences between desired and current state
- **Provider Operations**: API calls and responses to cloud providers
- **Resource Dependencies**: Graph construction and execution order

### Log Level Comparison

| Level | Description                | Use Case                |
| ----- | -------------------------- | ----------------------- |
| ERROR | Error messages only        | Production monitoring   |
| WARN  | Warnings and errors        | General troubleshooting |
| INFO  | Informational messages     | Workflow understanding  |
| DEBUG | Detailed debug information | Development debugging   |
| TRACE | Maximum verbosity          | Deep troubleshooting    |

## Providers & Resources

### API Call Debugging

Debug logs reveal:

- **HTTP Requests**: Method, URL, and payload details
- **Response Codes**: Status codes (HTTP 200, 404, etc.)
- **Provider Versions**: Which provider versions are being used
- **Authentication**: How providers authenticate with services
- **Resource Attributes**: Detailed resource property inspection

### Provider Registry Interactions

Logs show:

- Registry lookups at `registry.terraform.io`
- Provider download and installation process
- Version constraint resolution
- Plugin directory scanning

## Pitfalls & Best Practices

### Critical Considerations

- **Performance Impact**: Logging adds overhead, especially at TRACE level
- **Sensitive Data**: Logs may contain sensitive information like API keys
- **Log File Size**: TRACE logging can generate very large files
- **Environment Cleanup**: Always disable logging after debugging

### Common Mistakes

- Leaving debug logging enabled in production
- Not setting both `TF_LOG` and `TF_LOG_PATH` for file logging
- Using inappropriate log levels for the debugging task
- Sharing log files without sanitizing sensitive information

### Best Practices

- Use appropriate log levels for specific debugging needs
- Enable file logging for complex issues requiring analysis
- Disable logging immediately after debugging completion
- Review log files for sensitive data before sharing
- Use TRACE level only when maximum detail is required

## Key Terms & Definitions

- **TF_LOG**: Environment variable controlling Terraform logging verbosity
- **TF_LOG_PATH**: Environment variable specifying log file destination
- **TRACE Level**: Most verbose logging level showing all operations
- **stderr**: Standard error output stream where console logs appear
- **Provider Registry**: Public repository of Terraform providers

## Common Exam Traps

- **Both Variables Required**: File logging needs both `TF_LOG` and `TF_LOG_PATH` set
- **Log Levels**: TRACE is most verbose, ERROR is least verbose
- **Performance Impact**: Debug logging adds operational overhead
- **Environment Variables**: Different syntax between Linux/macOS and PowerShell
- **Persistent Logging**: Logs continue until variables are cleared
