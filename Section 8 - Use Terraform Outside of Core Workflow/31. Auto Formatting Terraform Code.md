# Auto Formatting Terraform Code

## Overview

Terraform provides the `fmt` subcommand to automatically format Terraform configuration files according to canonical style conventions. This command aligns code, fixes spacing, and ensures consistent formatting across all `.tf` files in a working directory.

---

## Concepts

### Terraform fmt Command

- **Purpose**: Automatically formats Terraform code to match HashiCorp's style conventions
- **Scope**: Operates on all `.tf` files in the current working directory
- **Output**: Lists files that were modified during formatting
- **Use Case**: Ensures code consistency before committing to version control

### Style Conventions Applied

- Aligns equal signs (`=`) in argument assignments
- Fixes indentation and spacing
- Standardizes block formatting
- Removes unnecessary whitespace

---

## Terraform Workflow

### Using terraform fmt

**Basic Usage:**

```bash
terraform fmt
```

**Line-by-line Comments:**

```bash
# Formats all .tf files in the current directory
# Returns the names of files that were modified
terraform fmt
```

**Code Walkthrough:**

- The `terraform fmt` command scans the current working directory for all Terraform configuration files (`.tf` extension)
- It applies HashiCorp's canonical formatting rules to each file
- Files are modified in-place
- The command outputs the names of files that were changed
- If no files need formatting, the command produces no output

## Practical Example

### Before Formatting

**Misaligned Code:**

```hcl
resource "random_string" "random"    {
  length = 10
  special = true
min_numeric = 6
      min_special = 2
min_upper = 3
}
```

**Line-by-line Comments:**

```hcl
resource "random_string" "random"    {  # Extra spaces before opening brace
  length = 10                            # Inconsistent spacing
  special = true                         # Unaligned equals signs
min_numeric = 6                          # Missing indentation
      min_special = 2                    # Excessive indentation
min_upper = 3                            # Missing indentation
}
```

### After Formatting

**Properly Formatted Code:**

```hcl
resource "random_string" "random" {
  length      = 10
  special     = true
  min_numeric = 6
  min_special = 2
  min_upper   = 3
}
```

**Line-by-line Comments:**

```hcl
resource "random_string" "random" {  # Proper spacing before brace
  length      = 10                   # Aligned equals signs
  special     = true                 # Consistent indentation (2 spaces)
  min_numeric = 6                    # All arguments properly indented
  min_special = 2                    # Equals signs vertically aligned
  min_upper   = 3                    # Uniform formatting
}
```

**Code Walkthrough:**

- The `random_string` resource generates a random string with specific constraints
- `length`: Total character count (10)
- `special`: Includes special characters (true)
- `min_numeric`: Minimum numeric characters (6)
- `min_special`: Minimum special characters (2)
- `min_upper`: Minimum uppercase letters (3)
- After running `terraform fmt`, all equals signs align vertically, indentation is consistent (2 spaces), and spacing is standardized

## Pitfalls & Best Practices

### Best Practices

- **Pre-commit Hook**: Run `terraform fmt` before committing code to version control
- **Team Consistency**: Ensures all team members follow the same formatting standards
- **Automated CI/CD**: Include `terraform fmt -check` in CI pipelines to verify formatting
- **Regular Usage**: Run after copying code from examples or documentation

### Common Mistakes

- **Manual Formatting**: Attempting to manually align code instead of using `fmt`
- **Skipping Format Checks**: Not running `fmt` before code reviews or commits
- **Ignoring Output**: Not reviewing which files were modified by the command

## Key Terms & Definitions

| Term                  | Definition                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------- |
| **fmt**               | Terraform subcommand that formats configuration files to canonical style                    |
| **Canonical Format**  | The official, standardized formatting style defined by HashiCorp                            |
| **Subcommand**        | A secondary command issued after the main `terraform` command (e.g., `init`, `plan`, `fmt`) |
| **Pre-commit Hook**   | An automated script that runs before code is committed to version control                   |

## Common Exam Traps

- **Question**: Does `terraform fmt` validate Terraform syntax?

  - **Answer**: No. `terraform fmt` only formats code style. Use `terraform validate` to check syntax and configuration validity.

- **Question**: Does `terraform fmt` modify files in subdirectories?

  - **Answer**: By default, `terraform fmt` only processes files in the current directory. Use `terraform fmt -recursive` to format subdirectories.

- **Question**: Can `terraform fmt` break working code?

  - **Answer**: No. The `fmt` command only changes whitespace and alignment. It does not alter the logical structure or functionality of the code.

- **Question**: What happens if you run `terraform fmt` on already-formatted code?
  - **Answer**: Nothing. The command will produce no output if all files are already properly formatted.

## Additional fmt Options

| Flag           | Description                                                                                                |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `-check`       | Check if files are formatted without modifying them (returns exit code 0 if formatted, non-zero otherwise) |
| `-diff`        | Display formatting differences without applying changes                                                    |
| `-recursive`   | Process files in subdirectories recursively                                                                |
| `-write=false` | Don't write changes to files (useful with `-diff`)                                                         |

**Example with flags:**

```bash
terraform fmt -check -recursive
```

**Line-by-line Comments:**

```bash
# Check formatting in current directory and all subdirectories
# Returns exit code 3 if any files need formatting
# Does not modify files
terraform fmt -check -recursive
```
