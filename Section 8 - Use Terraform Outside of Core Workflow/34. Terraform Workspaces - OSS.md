# Terraform Workspaces - Open Source

## Overview

Terraform workspaces enable organizations to adopt DRY (Don't Repeat Yourself) principles by using the same codebase for different environments (development, staging, production). Workspaces organize infrastructure by environments and variables within a single directory, with each workspace maintaining its own isolated state file.

## Concepts

### Workspace Fundamentals

- **Default Workspace**: Every Terraform configuration starts with a "default" workspace that cannot be deleted
- **State Isolation**: Each workspace maintains separate state files, preventing environment conflicts
- **Same Codebase**: Use identical Terraform configuration across multiple environments
- **Environment Separation**: Deploy to different regions or accounts while maintaining code consistency

### Key Benefits

- Eliminates code duplication across environments
- Provides state isolation between deployments
- Enables environment-specific variable management
- Supports rapid environment provisioning

## Terraform Workflow

### Basic Workspace Commands

```bash
terraform workspace show
terraform workspace list
terraform workspace new <workspace-name>
terraform workspace select <workspace-name>
terraform workspace delete <workspace-name>
```

**Line-by-line Comments:**

```bash
# Display current active workspace
# List all available workspaces
# Create and switch to new workspace
# Switch to existing workspace
# Remove workspace (cannot delete default)
```

**Code Walkthrough:**
The workspace commands manage state isolation. The `show` command displays your current context, `list` shows all available workspaces, `new` creates and automatically switches to a new workspace, `select` changes active workspace, and `delete` removes unused workspaces.

### Workspace Creation and Switching

```bash
terraform workspace new development
terraform workspace select default
terraform workspace select development
```

**Line-by-line Comments:**

```bash
# Create "development" workspace and switch to it
# Switch back to default workspace (us-east-1)
# Switch to development workspace (us-west-2)
```

**Code Walkthrough:**
Creating a new workspace automatically switches to it and provides an empty state. Switching between workspaces changes which state file Terraform references, allowing the same configuration to manage different infrastructure deployments.

## Providers & Resources

### Region-Specific Provider Configuration

```hcl
provider "aws" {
  region = "us-west-2"
  default_tags {
    tags = {
      Environment = terraform.workspace
      Owner       = "TF Hands On Lab"
      Project     = "Infrastructure as Code"
      Terraform   = "true"
    }
  }
}
```

**Line-by-line Comments:**

```hcl
# Configure AWS provider for us-west-2 region
# Apply default tags to all resources
# Tag resources with current workspace name
# Identify resource owner
# Specify project classification
# Mark resources as Terraform-managed
```

**Code Walkthrough:**
The provider block defines the target AWS region and applies consistent tagging across all resources. The `terraform.workspace` interpolation automatically populates the Environment tag with the current workspace name, enabling easy identification of environment-specific resources.

## State Management

### Workspace State Isolation

Each workspace maintains completely separate state files:

- **Default workspace**: Manages infrastructure in primary region/environment
- **Development workspace**: Manages infrastructure in development region/environment
- **State verification**: Use `terraform show` to view workspace-specific state

### State File Behavior

- New workspaces start with empty state
- State changes only affect the active workspace
- Switching workspaces changes state context immediately
- Each workspace tracks its own resource lifecycle

## Modules & Variables

### Workspace Interpolation

```hcl
tags = {
  Environment = terraform.workspace
  Owner       = "Acme"
  Provisioned = "Terraform"
}
```

**Line-by-line Comments:**

```hcl
# Dynamically set environment tag to workspace name
# Static owner identification
# Mark resource provisioning method
```

**Code Walkthrough:**
The `terraform.workspace` interpolation sequence provides the current workspace name as a variable within your configuration. This enables dynamic tagging and resource naming based on the active workspace, improving resource organization and identification.

## Pitfalls & Best Practices

### Critical Considerations

- **Workspace Awareness**: Always verify current workspace before applying changes
- **State Isolation**: Remember that workspaces provide complete state separation
- **Region Consistency**: Ensure provider configuration matches intended deployment target
- **Naming Conventions**: Use descriptive workspace names that clearly identify environments

### Common Mistakes

- Forgetting to switch workspaces before deployment
- Assuming shared state between workspaces
- Inconsistent provider configuration across workspaces
- Deleting workspaces with active infrastructure

### Best Practices

- Use `terraform workspace show` before any deployment
- Implement consistent tagging with workspace interpolation
- Document workspace-to-environment mappings
- Regularly audit workspace usage and cleanup unused workspaces

## Key Terms & Definitions

- **Workspace**: Isolated environment for Terraform state management
- **Default Workspace**: Initial workspace that cannot be deleted
- **State Isolation**: Separate state files prevent cross-environment conflicts
- **Workspace Interpolation**: `terraform.workspace` variable for dynamic configuration
- **DRY Principle**: Don't Repeat Yourself - reuse code across environments

## Common Exam Traps

- **Workspace Deletion**: Cannot delete the default workspace
- **State Sharing**: Workspaces do NOT share state between environments
- **Automatic Switching**: Creating new workspace automatically switches to it
- **Empty State**: New workspaces start with completely empty state
- **Provider Context**: Provider configuration affects all resources in active workspace
